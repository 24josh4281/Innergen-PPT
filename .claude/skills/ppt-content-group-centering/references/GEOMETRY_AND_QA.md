# 계산식 · 예외 · 품질 검수

## 1. 이름

- 문제: **상단 쏠림** (콘텐츠 그룹 수직 중앙 정렬 실패, Content Block Vertical Centering Failure)
- 증상: 컨테이너 안 상하 여백 불균형 (Vertical Padding Imbalance)
- 목표: 그룹 단위 수직 중앙 정렬 (Group-level Vertical Centering)
- 목차: **목차 하단 공백** (TOC Bottom Void) — 목표는 목차 영역 채우기 (TOC Zone Fill)
- 본문: **본문 하단 공백** (Page Bottom Void, CB03) — 목표는 본문 영역 채우기. `출처 줄 위 − 마지막 개체 아래 ≤ 0.06 × 페이지 높이`

## 2. 계산식

배경 상자 B = [bx, by, bw, bh], 보이는 콘텐츠 그룹 G = [gx, gy, gw, gh], 안전 여백 pt · pb · pl · pr.

```
gy* = by + (bh − gh) / 2
Δ   = gy* − gy                      # 모든 요소에 같은 Δ를 더한다
gapTop    = gy* − by
gapBottom = (by + bh) − (gy* + gh)
|gapTop − gapBottom| ≤ max(6px, 0.12·bh)
gapTop ≥ pt,  gapBottom ≥ pb
gx ≥ bx + pl,  gx + gw ≤ bx + bw − pr
```

예: 카드 높이 110px, 그룹 높이 52px → 위·아래 모두 29px. 숫자와 설명 사이 간격은 그대로 둔다.

### SVG 글자의 보이는 범위

SVG `<text y>`는 기준선(baseline)이다. 줄마다 아래 값으로 범위를 잡는다.

| 줄 내용 | 위 (기준선 기준) | 아래 |
|---|---|---|
| 한글 포함 | −0.78em | +0.12em |
| 숫자·대문자만 | −0.72em | +0.02em |
| g·j·p·q·y 포함 영문 | −0.72em | +0.21em |

측정 글꼴: IBM Plex Sans KR (0.77/0.12), Pretendard (0.79/0.09), 맑은 고딕 (0.85/0.09). 맑은 고딕은 위가 조금 더 높다.

## 3. 글상자 경계 ≠ 보이는 경계

PowerPoint 글상자 높이는 보이는 글자 높이와 다르다. 차이를 만드는 것은 다음 일곱 가지다.

- 안쪽 여백(inset)
- 글꼴의 ascent·descent
- 여러 줄
- 대체 글꼴
- 줄간격·단락 간격
- 자동 맞춤
- 그룹 변환

새로 만들 때는 측정한 글자 높이에 맞춰 글상자를 딱 맞게 만든다. 기존 슬라이드는 렌더 이미지를 보고 판단한다. 기하학적으로 가운데여도 눈에 다르게 보이면 렌더 결과를 따른다.

PPT Master의 SVG→PPTX 변환은 글상자를 `anchor="t"`, 안쪽 여백 0으로 만든다. 그래서 SVG에서 맞춘 위치가 PPTX에 그대로 간다. 고치는 곳은 SVG 작성 단계다.

## 4. 우선순위

1. 글자가 모두 보이고 상자를 넘지 않는다.
2. 최소 글자 크기와 읽기 쉬운 줄바꿈을 지킨다.
3. 요소 사이 위계와 간격을 보존한다.
4. 그룹의 상하 여백이 같다.
5. 원래 상자 높이와 스타일을 보존한다.

넘치면 원래 높이를 고집하지 않는다. 상자 키우기나 문구 줄이기를 제안하고 승인을 받는다. 수치·사실·문구의 뜻은 자동으로 바꾸지 않는다.

## 5. 예외

| 경우 | 처리 |
|---|---|
| 제목 + 구분선 1개 + 본문 카드 | 제목 영역은 그대로 둔다. 본문만 구분선 아래 영역의 가운데에 둔다 |
| 구분선이 둘 이상인 목록 | 행 구분선이다. 목록 전체(구분선 포함)를 한 덩어리로 옮긴다 |
| 상자 가장자리에 붙은 강조선·머리띠·모서리 태그·왼쪽 막대 | 그룹에서 뺀다. 머리띠가 있으면 머리띠 아래부터를 컨테이너로 본다 |
| 이미지나 안쪽 패널이 상자 높이의 85% 이상을 채움 | 프레임으로 보고 검사하지 않는다 |
| 표의 행 띠(넓고 납작한 사각형) | 표 규칙을 따른다(셀마다 가운데). 일부 행만 옮기지 않는다 |
| 차트 범례·축 | 차트 배치 규칙을 따른다 |
| 같은 카드가 격자로 여러 개 | 카드마다 따로 가운데 정렬한다. 행·열 분배는 별도 작업이다 |
| 구조화 템플릿 자리(placeholder) | 자리 경계와 함께 템플릿에서 고친다. 슬라이드에서 글자만 옮기지 않는다 |

## 6. 검수 체크리스트

- [ ] 모든 배경 상자와 콘텐츠 그룹의 대응이 정해졌는가
- [ ] 의미가 이어진 요소가 한 덩어리로 움직였는가
- [ ] 숫자와 설명 사이 간격이 그대로인가
- [ ] 왼쪽 정렬 기준선이 그대로인가
- [ ] 위·아래 여백이 허용 오차 안인가
- [ ] 네 방향 모두 안전 여백을 지키는가
- [ ] 긴 설명, 2줄 이상, 대체 글꼴에서도 괜찮은가
- [ ] 목차 마지막 행 아래 공백이 페이지 높이의 10% 이하인가
- [ ] 개체가 편집 가능한 상태인가
- [ ] 실제 PPTX 렌더 이미지로 확인했는가 (못 했으면 "검증 미수행")
