# 이너젠 스타일 재사용 프롬프트

최신 [교육용 구획·간격·강조·메시지 프롬프트 v7](prompt-hierarchy-v7.md)을 우선한다. 흩어진 본문 설명에 의미 구획을 부여하고, 중요한 조건을 볼드·파란 볼드·빨간 밑줄로 선택 강조하며, 기억·대비할 조건과 증빙을 구체적으로 작성한다.

상세 교육자료 글자 크기에는 [최신 본문 프롬프트 v6](prompt-hierarchy-v6.md)를 우선한다. 본문 12pt·본문 소제목 14.5pt로 축소하며 제목 24pt·거버닝 20pt·출처·푸터는 유지한다. 아래 이전 본문 14pt 지정은 v6로 대체한다.

교육자료에는 [최신 번호·목차·거버닝 프롬프트 v5](prompt-hierarchy-v5.md)를 우선 적용한다. 목차는 2페이지, 본문은 대주제/세부 항목 번호, 거버닝은 20pt와 위아래 여백 균형, 본문은 14pt이다.

이 작업 폴더에서는 “이너젠 스타일로 만들어줘”가 저장된 규칙을 불러온다. 아래 프롬프트는 내용을 구체화하거나 다른 작업 환경에 규칙 파일을 함께 전달할 때 사용한다.

## 1. 공통 프롬프트

```text
제공한 자료로 이너젠(INNerGEN) 스타일의 편집 가능한 PPT를 만들어줘.

자료: [현재 프로젝트의 원자료 경로 또는 내용]
용도와 독자: [제안 / 착수 / 최종보고 / 교육, 대상 독자]
장수: [요청 장수 또는 내용에 맞춰 제안]
규격: 별도 요청이 없으면 원본과 같은 13:9
스타일 변형: 별도 지정이 없으면 classic-grid

docs/styles/innergen/design.json, design.md, design-rules.md와
design-hierarchy-v4.md·json, prompt-hierarchy-v4.md를 읽고 최신 규칙을 적용해.
상단은 메인 제목 / 부제목, 그 아래는 ~입니다/합니다 체 거버닝으로 구분해.
구조화 본문은 명사형, 내용이 많으면 형식체 최종 메시지 박스를 넣어.
단어 경계 줄바꿈과 표 가로·세로 가운데 정렬을 검사해.
이너젠 원본의 남색 구조색, 흰 본문, 분류형 제목, 거버닝 문장,
회색 표·단계도·비교 구획, 필요한 빨간 강조를 재현해.
본문 장표는 자료를 설명하는 표·차트·절차 중심으로 설계하고,
회사 로고는 검증된 이너젠 자산을 사용해.
고객 로고는 이번 프로젝트에서 제공한 파일만 사용해.

원본 참고 PPT의 고객명·과거 수치·날짜·저작권 문구는 새 내용으로 복사하지 마.
이번 자료의 수치·단위·합계·경계·출처는 보존하고, 불명확한 값은 표시해.
글꼴은 설치된 이너젠 폰트 계획을 따르고 대체가 있으면 명세에 남겨.
제목·본문·표·차트는 편집 가능하게 만들고 넘침·겹침·계산을 검사해.

기존 저장소 routing.md로 작업 경로를 고르고 해당 경로의 확인·검증 절차를 따라.
이 JSON을 프로젝트 spec_lock.md 대신 복사하지 말고,
이번 프로젝트의 디자인 명세와 잠금값에 적용 결정을 기록해.
```

## 2. 용도별 추가 문장

| 상황 | 추가 요청 |
|---|---|
| 제안서 | “배경·필요성, 과업 이해, 수행 범위, 방법, 일정, 산출물 순서로 구성해. 실적과 효과 수치는 제공한 자료만 사용해.” |
| 착수보고 | “수행 범위, 자료 요청, 담당과 역할, 세부 절차, 일정, 검토 시점을 명확히 보여줘.” |
| 최종보고 | “수행 내용과 검증된 결과, 근거, 한계, 보완과제를 구분해. 결과값을 새로 만들어 넣지 마.” |
| 보고서형 | “classic-grid로 표와 근거가 충분히 읽히는 밀도를 유지해.” |
| 간결한 인벤토리형 | “slim-line으로 흰 헤더·푸터와 얇은 남색 구분선을 적용해.” |
| 규제 결과 보고형 | “solid-navy로 단색 헤더와 간결한 푸터를 사용해.” |
| 16:9 발표용 | “16:9로 재배치하고 본문을 키워줘. 원본 화면을 가로로 늘리지 말고 과밀 장표는 나눠줘.” |
| 특정 원본 기준 | “스타일 원본은 [파일 경로]야. 그 자료의 변형·폰트·구성을 우선하고 내용은 이번 자료로 작성해.” |

정확한 원본 PPTX에 내용을 채우는 요청과, 원본 스타일을 참고해 새로 구성하는 요청은 실행 경로가 다르다. 현재 요청의 보존 조건과 새 자료를 먼저 따른다.
