# 이너젠 컨설팅 장표 내용 원칙 v32 (2026-10-21)

디자인 규칙(v17·v18·v22)과 장표별 문법(v20·qaqc-v21)은 이미 있다. 이 문서는 그 위에서 **AI가 쓴 내용이 컨설팅 수준인지**를 정하는 원칙이다. 대상은 목차, 거버닝 메시지, 본문, 본문 도식화, 엔딩 메시지 다섯 가지와 이를 잇는 스토리라인이다. 기계 규칙은 [content-principles-v32.json](content-principles-v32.json), 자동 검사는 `scripts/innergen_story_check.py`, AI 독립 검토 절차는 [content-review-v32.md](content-review-v32.md)다.

- 근거: `INPUTS/PPT 장표 참고(구조화)` 25개 PDF 중 고객 프로젝트 9종(교육·수행계획·월간·진단·격주·착수·주간·최종·보고서 초안), Big4 세미나·인사이트 9종, 보고서·메모·평가서 6종, `INPUTS/이너젠 PPT 장표 레퍼런스` 4개 업무 폴더 중 10개 보고 덱. 2026-10-21 분석. 고객명·수치는 근거 위치 확인용으로만 쓰고 새 장표에 옮기지 않는다(v20 §9-7). 레퍼런스는 이 문서에서 유형으로만 부른다(예: "진단 덱", "규제대응 최종").
- 우선순위: 현재 사용자 요청 → 프로젝트 `spec_lock.md`·확정 계획 → v20·v25 → 이 문서. 이 문서는 v20 규칙을 바꾸지 않고 **덱 전체의 논리**와 **근거 정합**을 더한다. 예외는 §3.3(보고형 장 간지)뿐이다.
- 레퍼런스의 공통 약점(이너젠 덱 포함): 엔딩에 주체·기한 없음, 재사용 장표의 장 태그·번호 미갱신, 라벨형 거버닝 연속, 다른 덱에서 복사한 결론 문장. v32 검사는 이 네 가지를 먼저 잡도록 설계했다.

## 2. 스토리라인 — 장표보다 먼저 쓴다

### 2.1 스토리라인 설계표(Strategist가 장표 계획 전에 작성)

AI는 원문을 순서대로 장표로 옮기는 경향이 있다. 그러면 "자료 나열"이 된다. 장표 계획표(`design_spec.md` §IX)를 쓰기 전에 아래 6칸을 먼저 채우고 계획표 위에 둔다.

| 칸 | 내용 | 예(가상) |
|---|---|---|
| 독자·결정 | 누가 이 덱을 보고 무엇을 결정하는가 | A사 ESG팀장 — 연결 산정 범위 확정 |
| 핵심 질문 | 독자의 질문 1개(v20 `reader_question`) | 2027년 공시 전에 무엇을 먼저 갖춰야 하는가 |
| 답(한 문장) | 엔딩에서 다시 말할 결론. 수치·기한 포함 | 데이터 범위·Scope 3·목표 관리 3가지를 2026년 말까지 갖춰야 함 |
| 근거 3개(MECE) | 답을 받치는 논점. 서로 겹치지 않고 빠짐없게 | ① 범위 차이 18개 법인 ② Scope 3 산정 3개 항목뿐 ③ 목표 미설정 |
| 장 구성 | 근거 1개 = 장 1개(배경·결론 장 추가 가능). 장명은 명사구 | Ⅰ. 공시 요구와 현황 Ⅱ. 연결 범위 Ⅲ. Scope 3 Ⅳ. 목표 관리 Ⅴ. 추진 계획 |
| 엔딩 메시지 | 답 + 다음 행동 `(주체) 기한까지 행동` | (이너젠) 11.15까지 범위 대사표 초안, (A사) 11.08까지 법인 목록 회신 |

- 착수→중간→최종으로 이어지는 과업은 착수 덱의 목적·과업 번호·산출물 예고를 이 표에 그대로 적고, 최종 덱은 **같은 번호로 회수**한다(레퍼런스: 정부 용역 최종보고가 착수 때 예고한 산출물 ①②를 Ⅱ·Ⅲ장에서 그대로 회수). 발주처 평가는 목적 부합성·방법 적절성·계약 이행(회의 n회·산출물 n종)·활용 가능성으로 이뤄진다(최종 평가서). 최종 엔딩은 이 네 축에 답한다.
- 문제 행렬이나 진단 프레임워크를 앞에서 정의하면, 뒤의 해법 장표 결론에 그 행·칸 이름을 다시 쓴다(`⇒ [행 이름]`). 자가진단 N번을 로드맵 Key Action에 "(자가진단 N)"으로 역참조한 세미나 덱이 가장 검사하기 쉬운 형태다.

### 2.2 고스트 덱 기준

- 본문 장표의 90% 이상에 거버닝이 있고(N01), 그중 70% 이상이 판단 문장이다(N02: `~니다/~음/~임/~됨/~필요/~예정`, 상태 괄호). 주제 라벨이 이어지면 고스트 덱이 끊긴다. 레퍼런스 월간 덱은 "[참고] 분석결과물 – ○○" 라벨이 17장 이어졌고, 결론은 다음 달 진단 덱에서야 나왔다.
- 연속 장표는 `현황 → 원인·갭 → 과제 → 효과·계획` 중 한 단계씩 나아간다. 앞 장과 핵심어가 거의 같으면(N23) 장을 합치거나 [참고]로 내린다.
- `[참고]`·`[첨부n]`·`[Back-up]`·`Appendix` 접두 장표는 근거 보관용이라 고스트 덱 검사에서 뺀다. 대신 본문 문장 끝에서 `[첨부1]`처럼 교차 참조한다.
- 다른 프로젝트의 거버닝·엔딩 문장을 복사하지 않는다(N29). 레퍼런스에서 서로 다른 고객의 2024·2025 최종보고 엔딩이 글자 단위로 같았다. 일반론이라 재사용된 것이다.

## 3. 목차

### 3.1 원칙

1. **장 수 2–6개.** 고객 프로젝트 덱은 2–5장, Big4 세미나는 3–5장이었다. 본문이 90장이어도 장은 늘리지 않고 절(`[1]`, `①`)로 나눈다(N10).
2. **장명은 명사구 4–20자, 대등한 문법.** "무엇을 다루는가"만 쓰고 판단은 거버닝으로 보낸다. 질문형과 명사형을 섞지 않는다(N11). "개요·결론·기타"처럼 어느 덱에나 붙는 이름 대신 대상·쟁점을 넣는다(N12).
3. **장 순서가 논증이다.** 유형별 정형:
   - 교육·세미나: 이해(정의·배경) → 영향(왜 중요한가) → 대응(무엇을 할까)
   - 착수: Why(배경·현황) → What(범위·목적) → How(추진방안·일정) → Ask(자료 요청·결정) → Trust(수행 체계·품질)
   - 주간: 일반 동향 → 비교 → 우리 회사 적용 판단 → 다음 단계
   - 진단: 프레임워크 정의(사실상 목차) → 측면별 현황·갭 → 과제 종합·우선순위 → Appendix
   - 최종·공시: 외부 표준 순서(예: 지배구조 → 전략 → 리스크관리 → 지표·목표) 또는 착수 과업 번호 순서 → 결과 요약 → 제언
   - 짧은 발표(10장 이하): 목차 대신 Why/What/How/Who/When 질문 프레임 1장
4. **목차의 모든 장이 본문에서 논증된다(N13).** 장명의 핵심어가 본문 제목·거버닝 어디에도 없으면 빈 장이다.
5. **마지막 장은 결론·제언·향후 계획 계열**로 목차에 올린다. 최종보고에서 "향후 제언"이 장으로 없으면 "감사합니다"로 끝나게 된다.

### 3.2 정합(재사용 장표에서 가장 많이 깨짐)

- 목차 장명 = 장 간지 = 본문 브레드크럼(`Ⅱ. 장명 – 절명`)은 같은 문자열이다(N14). 레퍼런스 오류: 이전 덱에서 가져온 장표의 장 태그 미갱신, "7대 이슈" ↔ "주요 이슈", "추진 방안" ↔ "추진 방향".
- 장 번호는 건너뛰지 않고(N16: "1." 다음 "3."), `(k/N)`은 분모가 같고 k가 중복·역순이 없다(N16). `첨부n` 번호는 덱 안에서 한 번만 쓴다(N15).
- 맺음(Thank you) 뒤에 본문 장표를 두지 않는다. 부록은 `[참고]`·Appendix로 표시한다(N17).
- 목차 쪽 범위는 최종 장수 확정 후 갱신한다(qaqc O02).

### 3.3 보고형 장 간지 (v20 §3 보완)

v20 §3은 "보고형은 장 구분 장표를 두지 않고 제목 접두 번호로 위치 표시"라고 정했다. 그러나 분석한 이너젠 보고 덱 6종은 모두 **목차를 장 간지로 다시 넣고 현재 장을 강조**했고, 외부 교육·세미나 덱도 같았다. v32부터 보고형도 다음 둘 중 하나를 쓴다. 기본값은 덱 길이로 정한다.

| 본문 장수 | 위치 표시 |
|---|---|
| 15장 이하 | 제목 접두 번호 + 푸터 장 라벨(v20 그대로) |
| 16장 이상 | 위 + 장이 바뀔 때 목차 재삽입(현재 장 강조, `02c` 또는 `toc` 변형) |

### 3.4 목차 자동 생성 (v33)

목차는 손으로 다시 쓰지 않고 본문에서 만든다. `toc_builder.py`가 본문 제목의 장 표시(`Ⅱ. 장명 – 절명`), 꼬리말 장 라벨, outline의 `chapter` 필드에서 장·절·쪽 범위를 모아 `02b_toc_pages_N`을 채우고, `--dividers`로 현재 장을 강조한 재삽입 목차를 만든다. 장 수 2–6, 장명 20자, 번호 순서를 같이 검사한다. 사용법은 [content-diagrams-v33.md](content-diagrams-v33.md) §5.

## 4. 거버닝 메시지

v20 §5의 문체·역할별 문장 틀·금지 표현을 그대로 쓴다. 아래는 레퍼런스에서 확인한 **내용 품질** 기준이다.

### 4.1 좋은 거버닝의 네 요소

| 요소 | 설명 | 레퍼런스 유형(의역) |
|---|---|---|
| 주어 | 판단의 주체·대상 | "회사는 ~합니다" 문장만 이어 붙이면 경영진 요약이 되는 최종보고 |
| 판단 | 사실 다음의 "그래서" — 하나를 골라 단정 | "시나리오 상 여러 위험 중 하천범람만이 중대한 재무영향 요인" |
| 기준점 있는 수치 | 전년·기준연도·BAU·목표·업계 대비 | "2018년 대비 13%p 증가", "BAU 대비 2030년 64% 감축" |
| 함의·행동 | 독자가 할 일·판단 | "2030년 내 중대하지 않으나 지속 모니터링 필요" |

- 결과 거버닝은 **값 + 기준연도 + 증감(Δ·%) + 원인**까지 쓴다("편의점 매장 감소에 따라 전년 대비 3.0% 감소"). 증감만 있고 원인이 없으면 본문에 원인 각주를 둔다(전년 대비 ±20% 이상).
- 거버닝의 수치는 같은 장표 본문(표·차트·칸)에 그대로 있어야 한다(N22). 원문(`sources/`)에서도 찾을 수 없으면 근거 없는 수치다.
- 거버닝의 개수 표현("4개 과업", "8대 결과", "7가지 이슈")은 본문 열거 수와 같다.
- 추정·전망 수치에는 `가정`·`개략 추정`·시나리오·민감도 단서가 본문에 있다(N28). 예상 감축량이면 산식(BE − PE − LE = ER)과 가정 안을 함께 둔다(산식은 편집 가능 수식, qaqc M01–M03).
- 최종보고 결과 장표는 완료형 + 완료 일자(`확정 완료('26.4.17)`)로 쓰고 `예정`을 남기지 않는다(N27). 향후·제언 장표는 예외.
- 같은 연도끼리 비교하는 오타(`2025년 … 2025년 대비`)는 오류로 본다(N26).

### 4.2 약한 거버닝(감점)

| 패턴 | 예(가상) | 검사 |
|---|---|---|
| 주제 라벨 | "물리적 리스크 분석 결과" | N02, qaqc G05·G08 |
| 내용 소개 | "Scope 3 경계를 검토합니다", "주요 내용은 다음과 같습니다" | N20 |
| 상투어 2개 이상 | "다양한 이해관계자와 적극적으로 협력해 체계적으로 관리" | N21 |
| 빈 약속 | "최상의 품질로 최선을 다해 수행" | N21 |
| 앞 장 반복 | 연속 2장의 거버닝이 같은 핵심어 | N23, qaqc G03 |
| 근거 없는 수치 | 거버닝 "40% 절감", 본문에 40% 없음 | N22 |

## 5. 본문

1. **근거 → 주장.** 본문 블록은 거버닝을 증명하는 사실·수치·기준이다. 거버닝에 명사 두 개가 있으면 블록도 두 개(예: "매출액과 사업체 수 역대 최대" → 차트 2개).
2. **블록 2–4개, 같은 문법.** 병렬 블록은 같은 구조(제목 + 대시 설명 + 괄호 보충)로 쓴다. 4개 넘으면 카드 그리드(v20 §6.2).
3. **4층 구조(데이터 장표).** 리드 문단(수치로 풀어 쓰기) → 차트·표 → 해석 bullet 2–3개 → 시사점 칸. 시사점 칸(`시사점`·`Key Findings`·`핵심 Focus`·`FIRST STEP`)은 장표당 하나, 거버닝 반복 금지(qaqc S04).
4. **일반 사실 뒤 고객 적용.** 교육·벤치마킹 사례 다음에 "[고객] Approach" 칸이나 현재 위치(Phase 1–4 중 어디)를 둔다. 레퍼런스 주간보고는 비교표 → 고객 적용 판단 → "의사결정 필요"로 닫았다.
5. **근거 규율.** 수치가 4개 이상인 장표는 출처·단위·기준시점을 둔다(N24, qaqc C04). 자체 분석이면 `출처: [툴]을 바탕으로 이너젠 분석`, 추정치는 `(E)`·`가정`, 계수·GWP는 버전과 조항(`AR5`, `[별표 6]`)까지.
6. **판단 기준은 숫자로.** 중대성·우선순위 기준은 금액 하한·비율·발생 시점·척도표로 정의한 뒤 판정한다.
7. **업무별 추적.** CDP는 문항 ID로 요구 → 응답 → 감점 → 개선을 잇고, 감축사업은 판정표(항목 × 기준 × 사실 × ○)와 대안 비교(채택/기각 + 사유), 규제대응은 법정 기한(명세서·정산·이행계획서)을 거버닝에 쓰고 일정을 역산한다. 업무별 필수 항목은 v25 B01이 검사한다.
8. **요청 장표.** 요청물 × 대상 × 기간 × 용도 × 형태 × 기한 × 담당(v20 §6.3) + 규명 대상(왜 필요한가)과 차수(`1차_251205`). 계정·비밀번호는 요청하지 않고 "시스템 접근 권한 협의"로 쓴다(N25).

### 6.2 고르는 기준과 라벨

- 순서·인과·포함이 메시지면 도식, 속성 비교·갭 진단이면 표, 규모·추세면 차트(해석 bullet 동반), 정의·제도 개요면 라벨 박스 + bullet. 외부 툴 원출력은 `[참고]`로, 해석은 별도 장표에서.
- 순서가 없는 병렬 항목에 화살표를, 위계가 없는 항목에 피라미드를 쓰지 않는다. 축 이름 없는 매트릭스는 쓰지 않는다.
- 도식 안 라벨은 2–6어절 명사구, 행위 단계는 `목적어 + 행위명사`("리스크·기회 목록화", "중대성 평가"). 화살표 라벨은 "원인 → 결과" 압축구.
- 도식은 결론 띠(문장 하나)로 닫는다. 해석을 청중에게 맡기지 않는다.
- 프레임워크를 한 번 정의하면 이후 장표에서 같은 골격을 반복하고 현재 칸만 강조한다(진단 덱의 S-G-R-M 4회 반복, 착수 셰브런을 최종에서 같은 모양으로 재사용하고 완료 표시만 바꾸기).

### 6.3 같은 내용, 여러 도식 (v33)

같은 내용도 2–3가지 도식으로 그릴 수 있다. 이 기능은 선택이다. 목차 체크리스트(`analysis/diagram_select.md`)에서 "여러 도식 후보 보기"를 체크한 장·장표만 `content_diagrams.py`로 후보 3개를 그려 비교한 뒤 하나를 고르고, 나머지는 도식 1개로 쓴다. 대상 선정·관계 추론·후보 순위는 [content-diagrams-v33.md](content-diagrams-v33.md)가 정한다.

### 7.2 엔딩 원칙

1. **첫 장 질문에 답한다(N40).** 도입 3장의 핵심어가 마무리 3장에 다시 나온다. 표지 제목의 "대응전략"이 결론 장표 헤더 질문으로 돌아오는 것이 모범이다.
2. **핵심 메시지 3개 이내**, 이 과업의 수치·대상으로 쓴다. 어느 고객에게나 맞는 문장이면 다시 쓴다(N29).
3. **다음 행동 = `(주체) 기한까지 행동`.** 보고형(제안·착수·주간·격주·월간·진단·중간·최종·경영진)은 마지막 3장에 주체와 기한이 있어야 한다(N41, 덱 단계에서 ERROR). "감사합니다", "최선을 다하겠습니다"만으로 닫지 않는다(N42).
4. **결론 장표가 있다(N44).** 마지막 본문 3장 안에 결론·시사점·Takeaways·제언·향후 계획·결정 요청 장표가 있어야 한다. 마지막 사례 장표 다음 바로 면책·연락처로 끝나는 덱(레퍼런스 교육 92장, 월간 41장, 국내 정부 용역 최종보고)은 약한 엔딩이다.
5. **'해당 없음'도 결론이다.** 결론 → 단서 → 조건부 행동 3단("현재 CBAM 대상 품목 없음 → 확대안에 해당 품목 있음 → 유럽 수출 시 제조사 배출량 요청").

## 10. 한계

- 자동 검사는 텍스트 패턴이다. "판단이 맞는가", "근거가 충분한가", "MECE인가"는 AI 검토와 사람 검토가 본다(content-review-v32 §3).
- 레퍼런스 PDF 중 이미지 PDF 2종과 제목이 이미지인 1종은 렌더로 읽었다. 수치 일부는 판독 오차가 있을 수 있어 원칙만 가져오고 수치는 옮기지 않았다.
- 합계·비율 재계산, 개수 표현 ↔ 열거 수, 계수 버전 정합은 표 구조 해석이 필요해 이번 자동 검사에 넣지 않았다. AI 검토 `body` 항목에서 본다.
