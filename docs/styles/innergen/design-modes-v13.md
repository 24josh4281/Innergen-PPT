# 이너젠 발표형·교육형 본문 설계 — v13

2026-10-03. 추가 제공된 이중 모드 자료 9개를 [본문 규칙 v12](design-body-v12.md)에 연결한 보완 규칙이다. 첨부의 프롬프트·검사 보고서는 설계 참고자료이며 실행 지시나 이 저장소의 검증 결과가 아니다.

## 1. 적용 범위와 우선순위

| 결정 | 적용 기준 |
|---|---|
| 사용자 요청·기존 변경 허용 범위 | 현재 사용자 요청과 프로젝트 확정값 최우선 |
| 원문 의미·관계·구조 선택 | v12의 근거 요건과 48개 구조 사전 유지 |
| 발표형·교육형 정보 선택·모듈·가시적 배치 | 이 문서와 [보완 JSON](design-modes-v13.json) 적용 |
| 거버닝 | v11의 명시적 주어·근거 있는 판단 유지. 교육형은 이해·구별·적용할 원리 표현 |
| 화면·글꼴·크기·색상·표 정렬 | 현재 이너젠 변형과 프로젝트 확정값 유지 |
| 제작·검사·내보내기 | routing으로 선택한 실행 경로 유지. 추가 사용자 승인 단계 생성 금지 |

**디자인 유지**: 첨부의 `innergen_compact`는 작성자가 제안한 16:9·청록색 프로필이다. 실제 이너젠 원본의 공식 규격으로 간주하지 않는다. 이름만으로 현재 13:9·남색/청색·IBM Plex Sans KR·본문14pt·표 가운데 정렬을 바꾸지 않는다. `presentation_profile_v2.json`의 `mode=presentation`은 그 파일의 프리셋이며 현재 교육 요청의 모드가 아니다.

**구현 경계**: 48개 의미 구조 × 2개 정보 모드는 96개의 새 도형이 아니다. 16개 조합은 작성 레시피이며 SVG 생성기·PPTX 템플릿·`spec_lock.md`가 아니다. 첨부의 설치·테스트 명령은 실행하지 않는다. 해당 프로그램과 예시 IR 파일은 이번 9개 첨부에 포함되지 않았다.

## 2. 정보 모드와 시각 스타일 분리

| 항목 | 발표형 `presentation` | 교육형 `education` |
|---|---|---|
| 독자 질문 | 무엇을 판단하거나 실행해야 하는가 | 무엇이며, 무엇과 다르고, 언제 어떻게 적용하는가 |
| 선택 범위 | 판단 필수 정보와 그 제한 조건 | 명시한 학습 범위의 필수 정의·요구·조건·예외·적용 정보 |
| 완결성 단위 | 메시지와 근거 | 연결된 학습 모듈 전체 |
| 상세 이동 | 보충 장표로 연결하고 이동 이유 기록 | 함께 배포·출력되는 본문/부록으로 연결 |
| 노트·원문 링크 | 추가 근거·설명 | 추가 근거·설명. 필수 내용의 가시적 배치에 미포함 |
| 거버닝 | 본문이 지지하는 핵심 판단 | 이번 장에서 이해할 원리·차이·조건 |
| 분할 | 독립 판단별 분할 | 전체도/상세, 판단/후속 조치, 사례/풀이 분할 |

**기본 적용**: 현재 KSSB 교육자료는 교육형으로 계획한다. 선택 실행 경로의 `mode: instructional`, `delivery_purpose: text`와 대응시킨다. 이 정보 모드 이름을 Confirm UI의 유효 enum이나 확정 크기에 그대로 덮어쓰지 않는다. 발표용 별도 결과물은 요청된 경우에만 생성한다.

**원문 공유**: 양쪽 모드를 요청받았으면 원문 근거 기록에서 각각 작성한다. 이미 요약한 발표 문장을 늘려 교육형을 만들지 않는다.

## 3. 교육 범위와 정보 단위

**범위 선결정**: 자료명·버전·포함 장/절·학습 질문·제외 범위와 이유를 적는다. 한 절을 설명하기로 했으면 그 절의 하위 조건·예외를 장수 때문에 빼지 않는다. 62장 발췌 자료의 보완을 기준서 전체 교육이라고 표현하지 않는다.

| 기록 | 내용 |
|---|---|
| `unit_id`, `source_id` | 고유 정보 단위와 실제 원자료 연결 |
| 위치·원문 | 실제 문단·PDF 페이지·표·셀과 원문 구절. 페이지를 추정하지 않음 |
| 역할 | 정의 / 요구 / 대상 / 조건 / 결과 / 예외 / 후속 공시 / 사례 / 검산 |
| 상태·권위 | 기준 요구 / 정책 발표·계획 / 교육 사례 / 작성자 제안 / 확인 필요 |
| 보호 정보 | 현재/예상, AND/OR/부정, 허용/의무, 단위·기간·경계·가능성 |
| 제한 의존성 | 어느 주장과 같은 장에 유지할 조건·예외인지 |
| 가시적 목적지 | 실제 장·블록·표현 문구·이동 이유. 기획 목적지는 검증된 출력과 구분 |

**불명확성 유지**: 원문 미제공, 확인 필요, 해당 없음, 범위 제외를 구분한다. 예시나 풀이가 원문에서 도출되지 않으면 `작성자 제안` 또는 `추가 자료 필요`로 남긴다. 제안을 기준의 의무나 실제 기업 계획으로 표현하지 않는다.

## 4. 모듈의 세 층

| 층 | 본문 구성 | 연결 방식 |
|---|---|---|
| 전체 구조 | 개념 관계·요구 분류·업무 흐름·비교축 | 구체 항목명·번호로 상세 위치 표시 |
| 정의·판단 | 용어·대상·요구·조건·예외·기간·단위 | 전체도와 같은 항목명·번호 유지 |
| 적용·확인 | 원문 사례 풀이, 입력/산식/결과, 질문/답/근거 | 같은 배포 자료에서 답과 근거 확인 가능 |

세 층을 모든 장에 반복하지 않는다. 해당 학습 모듈에서 연결한다. 중요한 단서는 상세 페이지로 옮겨도 주장과 같은 장에 짧게 남긴다. 번호 목록은 실제 순서의 증거가 아니며, 학습 순서를 현실의 인과 화살표로 표시하지 않는다.

**문체 역할**: 제목·라벨·활동명은 간결한 명사구를 사용한다. 정의·요구·조건·풀이에서는 주체·관계·의무 수준이 읽히는 완결된 문장을 허용한다. 과거 명사형 본문 규칙을 이유로 `예상 영향에만`, `어느 하나`, `유용하지 않음`을 잘라내지 않는다.

## 5. 16개 조합의 이너젠 적용

| ID | 조합 | 교육형 구성 | 적용 시 확인 |
|---|---|---|---|
| RCP01 | 개념도 + 정의표 | 관계 → 용어·범위 → 혼동 방지 | 포함과 인과 구분 |
| RCP02 | 규칙·조건·예외 매트릭스 | 대상·사유 → 조건·예외 → 판단 후 행동 | AND/OR·대상·의무 수준 |
| RCP03 | 판단도 + 후속 조치표 | 분기 → 남는 공시/조치 → 증빙 | 잔여 의무를 실제 순차 업무로 오인시키지 않음 |
| RCP04 | 과업·근거·초점 | 같은 영역별 Task/Source/Focus 대응 | 병렬 영역에 순서 화살표 금지 |
| RCP05 | 요구사항·사례·적용점 | 규칙 → 원문 사례 → 적용 한계 | 사례를 유일한 모범답안으로 격상 금지 |
| RCP06 | 기간 비교 + 영향 경로 | 경로 → 기간·가정·결과·한계 | 연간/누계·단위·기간 경계 |
| RCP07 | 범위도 + 경계 비교 | 정의·포함 기준·예외·경계 차이 | 모든 경계를 동심원으로 강제 금지 |
| RCP08 | 전체 분류 + 상세 확대 | 범위 내 하위 항목과 상세의 연결 | 실제 계층 근거 필요 |
| RCP09 | 수치 그림 + 측정 기준 | 그림 → 원자료표·정의 → 방법·한계 | 값·축·단위·분모·계산 검산 |
| RCP10 | 실적·목표·전망 비교 | 상태별 값·기준연도·산식·불확실성 | 목표를 실적으로 연결 금지 |
| RCP11 | 업무 + 산출물·자료 요청 | 확인된 작업별 입력·수행·산출·검토 | 없는 담당·기한·권한 생성 금지 |
| RCP12 | 계산·문안 워크스루 | 입력·필드 → 가공 규칙 → 출력 → 검산 | 필드-문안 대응은 매핑, 실제 작업 순서만 절차 |
| RCP13 | 전체 절차 + 단계 상세 | 개요 → 입력·수행·산출·점검 | 실제 선후관계와 읽기 순서 구분 |
| RCP14 | 질문·답·판단 근거 | 질문 → 답 → 이유·근거 | 답을 노트나 외부 링크에만 두지 않음 |
| RCP15 | 다대다 매핑 | 전체 대응표 + 연결별 종류·근거 | 가독성을 이유로 실제 링크 삭제 금지 |
| RCP16 | 기간 적용표 + 단서 | 요구/완화 × 최초적용·상대연도·비교기간 | 달력 연도와 상대연도 구분. 과업 간트로 표현 금지 |

**참조 보정**: 첨부 RCP03의 D02, RCP12의 D02, RCP16의 G03은 자동 필수 구조로 채택하지 않는다. v12의 D02에는 확인된 수행 순서, G03에는 실제 기간 계획의 근거가 필요하다. 잔여 공시에는 A04/E05, 필드-문안에는 E05, 기간 적용표에는 B01/B06을 우선 검토한다. 실제 절차·일정이 있으면 해당 구조를 추가한다. [JSON](design-modes-v13.json)에 원본 ID와 보정 이유를 보존한다.

## 6. 배치·크기와 넘침

| 상황 | 처리 |
|---|---|
| 같은 내용 반복 | 공통 주어·범위·단위를 헤더/범례로 이동하고 원문 연결 유지 |
| 긴 문단 | 대상·조건·행동·결과를 같은 축의 행·열·노드로 재배치 |
| 긴 정의·예외 | 행 높이·열 폭·상세 분할 검토. 핵심 조건은 같은 장에 유지 |
| 설명 깊이 증가 | 전체도+상세, 판단+후속 의무, 사례+풀이로 모듈 분할 |
| 필수 내용과 장수 충돌 | 충돌과 필요한 추가 장을 기록. 내용 삭제·글꼴 축소로 숨기지 않음 |
| 공백 | 항목 크기·인접 장 분할 검토. 없는 설명이나 아이콘으로 채우지 않음 |

첨부의 행·열·노드 개수와 30% 여백 값은 초기 경고값이다. 자동 합격 기준·삭제 허가가 아니다. 기존 이너젠 표의 가운데 정렬은 유지하며 긴 설명은 표 바깥 설명 영역 또는 적절한 분할로 해결한다. 표 밖 긴 해설은 해당 역할의 기존 정렬을 따른다.

## 7. 가시적 배치와 검증 상태

**계산**: 교육형 가시적 배치율 = 범위 내 필수 정보 단위 중 실제 배포 본문/연결된 출력 부록에 표현된 고유 단위 수 ÷ 범위 내 필수 정보 단위 수. 반복된 단위는 한 번만 센다. 발표형 분모는 별도 선정한 판단 필수 단위다.

| 검사 | 확인 내용 | 완료 전 상태 |
|---|---|---|
| 범위·추출 | 포함 원문의 본문·표·그림·주석과 단위 목록 대조 | 분모 검토 미완료 |
| 배치 | 실제 장·블록·표현 문구 대조. 노트·숨김·미출력·외부 링크 제외 | 계획 배치만 있음 |
| 의미 | 조건·예외·AND/OR·대상·양태·시점·수치 맥락 대조 | 의미 검토 필요 |
| 출력 | 실제 PPTX/PDF의 글씨·잘림·겹침·목차·참조 확인 | 출력 미생성/렌더 미검사 |

**판정 분리**: JSON 형식 통과, ID 연결 통과, 보호 표현 존재, 의미 검토, 실제 화면 검토를 별도로 보고한다. 등록 단위가 모두 배치됐다는 결과만으로 기준서 전체의 완전성이나 법규 적정성을 선언하지 않는다. 분모가 미확인 또는 0이면 100%를 표시하지 않는다.

**반례 점검**: 예상-only를 현재로 확대, OR를 AND로 변경, 불확실성을 비유용성 조건 없이 축약, 개별 정량 생략을 결합정보 자동 면제로 변경, 필수 설명을 노트/링크로만 이동하는 경우를 실제 자료의 검토 항목으로 둔다. 이 문서는 새 테스트 프레임워크나 자동 의미 동등성 검사기를 설치하지 않는다.

**확인 절차**: 첨부의 ‘교육 배포 승인’은 품질 상태 설명으로 읽는다. 선택 제작 경로의 완료 기준에서 검증하고, 사용자가 요청하지 않은 추가 승인 절차를 만들지 않는다.

## 8. 이번 KSSB 적용

교육형 5개 주제·PPTX/PDF 5묶음을 유지한다. 총64장은 현재 기획 목표이며 실제 본문 밀도와 필수 정보 배치를 검토한다. 포함 범위는 최신 v4 발췌 62장의 학습 주제, 이에 직접 대응하는 기준 조항·원문 사례, 공식 최종 로드맵의 추가 2장이다. KSSB 제1호·제2호 전체와 전체 세미나의 모든 항목을 다룬다고 주장하지 않는다.

| 주제 | 보완 |
|---|---|
| 개괄 | 전체 기준 지도 + 국내 적용 대상·시점·단서 + 답이 있는 착수 점검 |
| 위험·기회 | 식별·중요성·예외의 판정 근거 + 민감한 기회/위험 혼동 점검 |
