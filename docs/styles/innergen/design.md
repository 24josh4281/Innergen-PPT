# 이너젠 프레젠테이션 디자인

최신 [구획·간격·강조·학습 메시지 v7](design-hierarchy-v7.md)와 [JSON](design-hierarchy-v7.json)을 우선한다. 설명을 의미 구획 안에 배치하고 간격을 정렬하며 본문 중요어·조건을 볼드·파란 볼드·빨간 밑줄로 선택 강조한다. 거버닝과 최종 메시지는 기억할 조건과 준비할 근거를 구체적으로 짚는다.

상세 교육자료 글자 크기는 최신 [본문 축소 v6](design-hierarchy-v6.md)와 [JSON](design-hierarchy-v6.json)을 우선한다. 본문 12pt·본문 소제목 14.5pt이며, 이전 v3/v4/v5의 본문 14pt 지정만 대체한다. 제목·거버닝·출처·푸터는 유지한다.

최신 추가 규칙은 [번호·목차·상단 간격 v5](design-hierarchy-v5.md), [JSON](design-hierarchy-v5.json)이다. 교육자료 2페이지 목차와 제목/부제목 번호를 연결하고, 거버닝은 20pt로 헤더와 본문 사이의 실제 여백을 균형 있게 배치한다. 이 항목은 이전 크기·기준선보다 우선한다.

최신 사용자 피드백인 [정보 위계·문체 v4](design-hierarchy-v4.md)와 [JSON](design-hierarchy-v4.json)을 우선 적용한다. 제목/부제목은 분류·주제 명사구, 그 아래 거버닝은 ~입니다/합니다 체, 구조화 본문은 명사형이다. 상세 교육 본문은 14pt, 표는 가로·세로 가운데 정렬을 적용한다.

`INPUTS/이너젠 PPT 장표 레퍼런스`의 PPTX 19개, 573장에서 추출한 재사용 디자인 기준이다. 이 문서는 모델 자체를 재학습하는 파일이 아니라, 이후 이너젠 스타일 요청에 적용할 디자인 명세다. 실행 가능한 수치·선택지는 [`design.json`](design.json), 장표 제작·검사 기준은 [`design-rules.md`](design-rules.md), 재사용 프롬프트는 [`prompt.md`](prompt.md)를 따른다.

## 1. 기준과 우선순위

| 구분 | 적용 기준 |
|---|---|
| 관측값 `fact` | PPTX 구조·테마·텍스트·이미지에서 직접 확인한 값 |
| 시각 관측 `observed` | PowerPoint로 렌더링한 원본 장표에서 확인한 구성 |
| 설계 기본값 `default` | 여러 원본을 일관되게 재사용하기 위한 권장값. 모든 원본의 동일 수치라는 뜻은 아님 |
| 최신 요청 | 현재 사용자의 내용·페이지 수·명시한 규격·표현 방식이 우선 |
| 기본 스타일 | `classic-grid`. 지정된 원본이나 변형이 있으면 해당 변형을 사용 |
| 적용 범위 | 이 작업 폴더에서 “이너젠 스타일”, “이너젠처럼”, “INNerGEN style” 요청 시 |

외부 컨설팅사 PDF는 이너젠 색상·로고·폰트의 근거에 포함하지 않는다. 원본의 고객명, 수치, 기관 로고, 과거 날짜와 문구는 스타일이 아닌 개별 프로젝트 내용이다.

## 2. 화면 규격

| 항목 | 값 | 근거 |
|---|---|---|
| 원본 비율 | 13:9 | 19개 PPTX 모두 동일 `fact` |
| 원본 크기 | 780×540 pt = 10⅚×7½ inch | PPTX `p:sldSz` `fact` |
| 새 SVG 캔버스 | 1040×720 px, `viewBox="0 0 1040 720"` | 96 DPI에서 원본 PPT 실물 크기 보존 `default` |
| 도구 규격 키 | `ppt139` | 프로젝트 초기화·확인 화면·PPTX 변환에서 사용 |
| 좌표 변환 | SVG px = PPT pt × 4/3, PPT pt = SVG px × 3/4 | 동일 캔버스 사용 시 |
| 16:9 요청 | 1280×720 px로 재배치 | 헤더·표·열 너비를 다시 설계. 완성 장표 전체를 가로로 늘리지 않음 |

원본 크기의 작은 글씨를 16:9나 발표 화면에 그대로 적용하지 않는다. 읽는 보고서와 화면 발표용을 구분하고, 발표용은 내용을 나누고 본문을 키운다.

## 3. 스타일 변형

| 변형 | 특징 | 선택 기준 |
|---|---|---|
| `classic-grid` 기본형 | 남색 미세 격자 헤더·푸터, 우측 대각선 흰 영역, 회색 자료 프레임, 빨간 핵심 강조 | CDP·사업 제안·착수·밀도 있는 보고서 |
| `solid-navy` | 격자 없는 단색 남색 헤더와 간결한 푸터 | 규제대응 최종보고 원본에 맞출 때 |
| `slim-line` | 흰 헤더, 검은 제목, 얇은 남색 구분선, 흰 푸터와 작은 로고 | 인벤토리 제안서 V2·착수보고 원본에 맞출 때 |

변형은 새로운 브랜드 색상군이 아니다. 남색·흰색·회색이라는 동일한 구조색을 유지한다. 같은 덱 안에서 임의로 헤더·푸터 형식을 바꾸지 않는다. 정확한 지정 자료가 있으면 그 자료의 변형을 우선한다.

## 4. 색상

| 역할 | HEX | 적용 |
|---|---|---|
| 구조 남색 | `#0F243F` | 헤더, 푸터, 표지 띠. 원본 레이아웃 도형에서 확인 `fact` |
| 배경 | `#FFFFFF` | 본문과 표 셀 |
| 본문 | `#000000` | 제목·설명·표 값 |
| 회색 | `#808080` | 자료 제목 띠, 단계도·비활성 구간 |
| 연회색 | `#D9D9D9`, `#F2F2F2` | 구획, 보조 셀, 표 헤더 |
| 중간 회색 | `#BFBFBF` | 보조 선·약한 구분 |
| 의미 강조 | `#FF0000` | 핵심 요구사항, 위험, 차이, 검토 필요 항목 |
| 로고 색 | `#13387B`, `#286CB5`, `#80BFD7` | 확인한 원본 로고 파일에만 그대로 사용 |

표·도형에 직접 지정한 색과 테마 기본색은 구분한다. Office 테마의 `#4F81BD`가 자주 나타나도 이너젠 구조색으로 승격하지 않는다. 차트의 다계열 색상은 데이터 구분에 필요할 때 프로젝트별로 확정한다.

## 5. 글꼴과 크기

원본에는 맑은 고딕과 IBM Plex Sans KR가 주로 사용되며 HY견고딕·나눔스퀘어 등도 섞여 있다. 새 덱은 **Malgun Gothic(맑은 고딕)**을 기본으로 쓰고, 감축사업·규제대응 또는 인벤토리 제안서 V2를 기준으로 삼으면 **IBM Plex Sans KR**를 쓴다. 이는 연도순 규칙이 아닌 원본 분야·파일의 관측에 따른 선택이다. 특정 원본을 지정하면 그 자료의 주 폰트를 우선하고, 한글·영문·숫자는 같은 계열을 쓴다. 원본 PPTX를 직접 채우는 작업은 그 원본 폰트를 보존한다.

| 역할 | PPT pt 기본값 | 허용 기본 범위 | 스타일 |
|---|---:|---:|---|
| 표지 제목 | 36 | 28–44 | Bold, 남색, 2–3줄 이내 |
| 상단 장표 제목 | 24 | 20–28 | Bold, 기본형은 흰색 |
| 헤더 안 소제목 | 14 | 14–16 | 제목과 같은 줄 또는 별도 줄 |
| 첫 설명 문장 | 14 | 12–16 | 검정, Semibold/Bold, 1–2줄 |
| 자료 블록 제목 | 12 | 11–14 | Bold, 회색 띠 위 흰색 또는 검정 |
| 보고서 본문 | 12 | 10–14 | Regular, 필요한 단어만 Bold |
| 표 본문 | 10.5 | 9–12 | 셀의 가로·세로 가운데 정렬, 구분명 Bold; 상세 교육은 사용자 지정 14pt |
| 출처·주석 | 8 | 7–9 | 검정/회색 |
| 페이지 번호 | 10 | 9–12 | 흰색 또는 남색 |
| 푸터 법적 표기 | 6.5 | 6–8 | 필요한 발행 주체·연도만 기재 |

크기는 원본 전체의 평균이 아닌 **재사용 기본값**이다. 원본 역할별 관측 분포와 크기가 다른 경우가 있다. 발표용 권장 본문은 16–18 pt, 표는 12 pt 이상이며, 작은 글씨 대신 페이지 분할을 우선한다. 글꼴 대체 시 글자 폭과 줄바꿈을 다시 검사하고 프로젝트 명세에 기록한다. 이너젠 요청에 한정한 원본 계열 선호이며 다른 스타일의 Pretendard 기본값은 변경하지 않는다.

SVG 실행·확인 화면·`spec_lock.md`의 글자 크기는 **px**다. JSON의 `role_sizes_svg_px`를 사용한다. 예를 들어 본문 12 pt는 16 px, 제목 24 pt는 32 px, 표 10.5 pt는 14 px다. 원본 재현용 기본값을 확인 화면에 제안하되, 발표 목적이면 읽는 거리와 페이지 밀도에 맞춰 더 큰 값을 제안한다. 현재 사용자가 확인한 px 값을 다시 변환하거나 기본값으로 덮어쓰지 않는다.

## 6. 기본 본문 장표의 영역

다음 좌표는 780×540 **PPT pt** 기준의 제작 기본값이다. 원본의 반복 위치를 참조해 안전한 영역으로 정리했다. JSON의 좌표를 기준으로 세부 장표를 확정한다.

| 영역 | x / y / 너비 / 높이 pt | 내용 |
|---|---|---|
| 헤더 | 0 / 0 / 780 / 52 | 남색 바탕, 약한 격자, 우측 흰 대각선 |
| 제목 안전 영역 | 24 / 7 / 585 / 36 | 번호·장 제목·소제목. 고객 로고 영역 침범 금지 |
| 고객 로고 예약 영역 | 655 / 8 / 101 / 35 | 현재 프로젝트 로고가 있을 때만 사용 |
| 첫 설명 | 25 / 65 / 730 / 43 | 이번 장표의 대상·분석·의미 |
| 본문 자료 | 25 / 122 / 730 / 366 | 표·차트·비교·절차 등 |
| 푸터 | 0 / 500 / 780 / 40 | 회사 로고·필요한 법적 표기·페이지 번호 |

자료별 높이는 내용에 맞게 조정한다. 첫 설명이 필요 없는 부록·대형 표는 그 공간을 본문에 배분한다. 격자는 선명한 배경 패턴이 아니라 낮은 대비의 구조적 질감이다. 자료 본문에 격자 배경을 깔지 않는다.

## 7. 반복 장표 구성

| 장표 유형 | 구성 | 내용 선택 |
|---|---|---|
| 표지 | 흰 배경, 중심 또는 좌측 제목, 회사 로고, 남색 띠 | 과업명·보고 단계·현재 날짜·발행 주체 |
| 목차/구간 전환 | 좌측 관련 이미지 또는 단순 표식, 우측 번호 목록 | 해당 구간만 진하게, 나머지는 회색 |
| 요구사항/진단표 | 상단 설명 + 구분/요구사항/대응 표 | 법규·공시·평가 문항 비교 |
| 비교 | 좌우 동일 너비 + 공통 제목 띠 + 근거/해석 | 현황/목표, 기존/개정, 사례 A/B |
| 절차/방법론 | 회색 단계 띠 + 단계별 대상·방법·산출물 | 조사·분석·수집·검토·제출 |
| 일정 | 좌측 과업명 + 우측 기간 표와 작업 구간 | 검토 시점·책임자·제출물 구분 |
| 역할/범위 | 수행 조직·사업장·업무 경계의 표 또는 편집 가능한 도식 | 실체가 있는 관계만 표현 |
| 결과/개선과제 | 현황·근거·보완사항·담당·기한 | 검증된 결과와 조치 구분 |
| 근거/부록 | 큰 표 또는 원문 이미지 + 출처 + 핵심 주석 | 핵심 내용을 별도 편집 가능한 글자로 제공 |
| 마무리 | 간결한 감사 문구 또는 종료 메시지 + 회사 로고/남색 띠 | 자료 속 과거 회사·연도 복사 금지 |

자료를 모두 카드로 분할하지 않는다. 표·직선 구획·비교 패널·단계도를 목적에 맞춰 사용하며, 회색 프레임은 자료를 묶는 역할이다. 새 덱에 원본의 모든 장표 유형을 강제로 넣지 않는다.

## 8. 자산과 적용

회사 로고 원본은 `.claude/skills/ppt-master/templates/brands/innergen/images/`에 있다. 파란 로고는 흰 표지용, 흰 로고는 남색 푸터용이다. 비율·투명도·로고 문자를 유지한다. 원본 고객사와 협력사 로고는 공용 자산에 포함하지 않았다.

정체성만 필요한 명시적 브랜드 경로는 `.claude/skills/ppt-master/templates/brands/innergen/`이다. 이 문서와 JSON은 브랜드 정체성뿐 아니라 레이아웃 규칙도 포함하므로 **브랜드 preset 자체와 구별**한다. “이너젠 스타일”은 스타일 입력을 불러오며 템플릿 설치 경로를 자동 선택하지 않는다.

프로젝트마다 `design_spec.md`와 `spec_lock.md`에 확정 색상·글꼴·캔버스·페이지 구성을 기록한다. SVG 경로에서는 `visual_style: custom`을 사용하고 JSON의 `visual_style_behavior`를 복사한다. 생성·확인·검증·내보내기는 기존 저장소의 해당 실행 경로를 따른다.
# 최신 사용자 보완 규칙

[정보 위계·문체 v4](design-hierarchy-v4.md)와 [JSON](design-hierarchy-v4.json)을 먼저 적용한다. 상단은 분류형 메인 제목 / 부제목, 그 아래는 형식체 거버닝 문장이다. 구조화 본문은 명사형, 내용이 많으면 형식체 최종 메시지 박스를 둔다. 단어 경계 줄바꿈과 표 가로·세로 가운데 정렬은 이전 관련 조언보다 우선한다.
