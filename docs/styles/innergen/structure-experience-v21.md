# 구조 선택·미리보기 보완 v21

2026-10-14. [v19 실행 기준](consulting-structures-v19.md)의 선택 계약을 유지하면서
[v20 목차 규칙](content-architecture-v20.md)을 선택 화면과 작성 계획에 연결한다.
실행 도구는 `.claude/skills/ppt-master/scripts/consulting_structure.py`이며,
추가 데이터는 [structure-experience-v21.json](structure-experience-v21.json)에 있다.

## 1. 적용 범위

| 항목 | 동작 |
|---|---|
| 구조 예시 | v19의 14개에 26개를 보완하여 현재 등록된 40개 모두 구체적인 가상 내용으로 표시 |
| 추천 비교 | 추천 3개의 실제 HTML 구성 예시·용도·필요 자료를 나란히 표시하고 바로 선택 |
| 자료 전체 흐름 | 기존 사용 방식·보고 성격에서 8개 덱 유형을 추정하여 도입·본문·마무리 제안 |
| 사업 성격 | CDP·규제·감축·인벤토리 등 9개 업무의 확인 항목을 흐름 설명에 함께 표시 |
| 미디어 | 도식·원문 검색·혼합·생성 삽화의 배치 예시, 입력 자료, 제작 순서, 한계 표시 |
| 조작 유지 | 펼친 설명과 키보드 초점을 유지. 구조·비교 변경은 글자 크기·출처를 초기화하지 않음 |
| 적용 방지 | 오프라인 선택 파일 및 중간 확인 단계로 작성 계획을 확정할 수 없음 |

40개는 선택 가능한 장표 구성이다. 40개의 새 SVG 템플릿이나 PPT 출력 엔진을 만든
것이 아니다. 기존 `innergen_lecture` 템플릿과 v20의 5개 추가 구조는 그대로 보존한다.
HTML은 화면 크기에 따라 재배치되며 최종 PowerPoint의 좌표·글자 크기 검수를 대신하지 않는다.

## 2. 전체 자료 흐름

추가 필수 선택 없이 기존 값을 사용한다. 교육 사용 방식이 우선하고, 그 다음 제안
사용 방식 또는 제안 보고 성격을 적용한다. 나머지는 보고 성격에 대응한다.

| 선택 | 추정 유형 |
|---|---|
| 교육·강의 / 교육·배포 | `lecture` / `handout` |
| 제안 설명 또는 제안 보고 | `proposal` |
| 교육·워크숍 보고 + 일반 발표/읽기 | `seminar` |
| 착수 / 중간 / 최종 | `kickoff` / `interim` / `final` |
| 경영진 브리핑 | `briefing` |

v20의 16개 유형 중 위 8개를 자동 연결한다. 주간·격주 등 나머지 유형은 기존
기획 규칙으로 남으며 이 화면에서 모두 선택하도록 늘리지 않는다. 개별 장표 질문과
자료 전체 유형은 별도다. 교육 덱에서도 요구사항·진단 구조를 쓸 수 있다.

추정 목차는 현재 사용자 요청과 확정 목차·장수를 덮어쓰지 않는다. 기존 참고 장수와
레이아웃 ID를 사용자가 보는 흐름에 노출하거나 자동 설치하지 않는다. 핵심 지표는
검증된 원값이 있을 때만 넣고, 장수나 숫자 카드 수를 맞추기 위해 사실을 만들지 않는다.

## 3. 예시의 의미

모든 새 예시는 가상이다. 법령 시행일·고객 실적·승인 상태를 사실로 등록하지 않는다.
화면·사례 예시는 HTML로 만든 가상 기록이며 실제 제품 캡처가 아니다. 원본 캡처의
사용 가능 여부와 버전·위치는 실제 제작 작업에서 확인한다.

단계 흐름은 실제 선후관계에만 사용하고, 개념 지도와 과업 목록은 포함·병렬 관계로
구분한다. 히트맵은 상태 문자도 함께 표시하며 미확인은 0점이나 미이행이 아니다.
교육의 질문·정답·이유와 조건·예외는 가시적 본문에 남긴다.

## 4. 저장과 기존 프로젝트

확인 계약은 `structure_standard_version: "19"`, `structure_goal`을 유지한다.
`style_standard.py <project>`가 생성하는 `content_plan_v19.json/md`에는 다음이 추가된다.

| 필드 | 내용 |
|---|---|
| `experience_version` | `21` |
| `deck_story` | 추정 유형·도입/본문/마무리·필수 내용·문체·v20 참고 목차 |
| `business_requirements` | 선택 업무의 확인 항목 |
| `media_plan` | 예상 결과·입력·절차·한계·실제 선택된 출처·사용자 이미지 메모 |

계획의 `acquisition_status: not_started`는 검색·생성·다운로드가 아직 수행되지 않았다는
뜻이다. 상세 `image_usage`가 간편 선택과 다르면 상세 출처를 보존하고 차이를 알린다.
실제 획득은 기존 실행 경로의 이미지 단계에서 수행한다.

선택값과 v19/v20/v21 데이터가 바뀌면 기존 명세 점검에서 오래된 계획을 감지한다.
확정된 프로젝트는 필요할 때 다시 계획을 생성한다. 기존 프로젝트를 일괄 변경하지 않는다.
v19 미사용 프로젝트에는 내용 계획을 새로 강제하지 않는다.

오프라인 저장은 `status: simulation_selection, notApplied: true`이며 화면 펼침·비교
상태는 제외한다. `style_standard.py`와 `consulting_structure.py plan`은 기존 최종
확정 상태만 받는다. 새 승인 단계는 없다.

## 5. 사용·검증

```powershell
.venv/Scripts/python.exe .claude/skills/ppt-master/scripts/consulting_structure.py check
.venv/Scripts/python.exe .claude/skills/ppt-master/scripts/consulting_structure.py preview --output OUTPUTS/consulting-upgrade-v21/교육_제안_구조_비교_v21.html
```

로컬 점검은 40개 구체 예시·표 크기·30개 사용/보고 조합·9개 업무·4개 미디어·
4개 스타일·모바일 가로 넘침·선택 저장·3단계 값 보존을 다룬다.
합성 작성 계획 1,080개 사용/보고/업무/미디어 조합과 180개 스타일/사용/질문 조합을
확인한다. 이 점검은 실제 PPT 출력·규정 현행성·고객 원문 검수 결과가 아니다.

검수 산출물과 이번 변경 목록은 `OUTPUTS/consulting-upgrade-v21/보완_완료보고.md`에 기록한다.
