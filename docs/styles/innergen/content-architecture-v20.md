# 이너젠 본문 구조화·거버닝·목차 작성 규칙 v20 (2026-10-14)

`PPT 장표 참고.zip`의 레퍼런스 40건(약 1,900장)에서 **목차 골격, 제목 체계, 거버닝 메시지 문법, 본문 블록 배치, 시리즈·마무리 장표**를 추출해 이너젠 규칙으로 다시 쓴 문서다. 교육자료(TCFD 1차 교육 92장 등), 보고형(착수·주간·격주·월간 WG·진행현황·진단·과제·최종·경영진 요약·벤치마킹), 세미나·발표형(삼일PwC·회계기준원 등), 인사이트 리포트(삼정KPMG·딜로이트·EY), 요약 메모, 보고서 구성안을 모두 대조했다. 고객사명·수치·문장은 옮기지 않았고 구조만 가져왔다. 작업 기록은 `OUTPUTS/content-architecture-v20/`에 있다.

- 기존 규칙과의 관계: 제목·거버닝·본문·최종 메시지의 **역할 분담**은 [v4](design-hierarchy-v4.md), 목차 번호·쪽수는 [v5](design-hierarchy-v5.md), 거버닝의 주어·판단 원칙은 [v11](design-governing-v11.md), 원문 분해·구조 선택은 [v12](design-body-v12.md), 교육형·발표형 정보 모듈은 [v13](design-modes-v13.md)과 [v19](consulting-structures-v19.md), 보고 단계·업무별 장표 순서는 [v16](innergen-profile-matrix-v16.md), 구조화 레이아웃은 [v18](structured-slides-v18.md)을 그대로 쓴다. v20은 그 위에서 **덱 유형별 목차 골격과 거버닝·본문 작성 문법을 더 세밀하게** 정한다. 충돌하면 현재 사용자 요청 → 프로젝트 `spec_lock.md` → v20 → 기존 문서 순이다.
- 기계용 값: [content-architecture-v20.json](content-architecture-v20.json). 교육·강의(블루) 템플릿에 목차(쪽수)·장 구분·요구사항+Focus·사례 캡처·핵심 정리 레이아웃(`02b`, `02c`, `s21`~`s23`)을 추가했다.

## 1. 덱 유형과 문체

v19의 정보 모드(교육형·발표형·제안형·보고형)를 유지하고, 레퍼런스에서 실제로 구분되는 하위 유형을 더한다. 문체는 **덱 하나에 한 가지**만 쓴다.

| ID | 유형 | 모드(v19) | 독자 | 독자 질문 | 거버닝 문체 | 기본 장수 |
|---|---|---|---|---|---|---|
| `lecture` | 교육·강의(투사) | education | 수강생·실무자 | 무엇이며 언제 어떻게 적용하는가 | 완결 문장 `~합니다`, 주어 시작 | 30–90 |
| `handout` | 교육·배포 교재 | education | 읽는 실무자 | 위와 같음 | 위와 같음 | 30–90 |
| `seminar` | 세미나·강연·발표 | presentation | 외부 청중 | 왜 지금 중요한가, 무엇을 준비하는가 | 완결 문장 `~합니다`, 1문장 | 15–30 |
| `proposal` | 제안서·제안 발표 | proposal | 발주처·고객 의사결정자 | 왜 이 방안이고 무엇을 납품하는가 | 완결 문장. 수행 약속만 `~할 예정입니다` | 12–25 |
| `kickoff` | 착수보고 | report | 고객 실무·임원 | 무엇을, 어떤 순서로, 무엇을 받아서 하는가 | 개조식 `~음/~됨/~필요함` + 약속 `~예정입니다` | 10–20 |
| `weekly` | 주간 진행보고 | report | 고객 실무 | 이번 주 무엇을 확인했고 다음에 무엇을 하는가 | 개조식 | 10–20 |
| `biweekly` | 격주 미팅 자료 | report | 고객 실무 | 기준일 현재 진행·향후 계획·요청 | 개조식, 본문 2장 | 2–3 + 첨부 |
| `monthly` | 월간 WG·진행현황 | report | 워킹그룹·운영위 | 과업별 어디까지 왔고 무엇이 나왔는가 | 개조식, 상태 괄호 | 25–50 |
| `diagnosis` | 진단·개선과제 도출 | report | 고객 실무 워크숍 | 기준 대비 어디가 비었고 무엇을 고치는가 | 개조식, 판단은 `~것으로 분석됨` | 30–50 |
| `interim` | 중간보고 | report | 고객 임원 | 잠정 결과와 결정 요청 | 완결 문장 | 10–18 |
| `final` | 최종보고 | report | 고객 임원·발주처 | 무엇을 했고 무엇이 남는가 | 완결 문장 `~했습니다/~할 수 있습니다` | 20–40 |
| `briefing` | 경영진 요약(1–3장) | presentation | 경영진 | 결정할 것은 무엇인가 | 거버닝 대신 우측 시사점 박스 | 1–3 |
| `benchmark` | 벤치마킹 | report | 고객 실무 | 동종사 대비 어디가 부족한가 | 개조식, 판단 1문장 | 10–20 |
| `insight` | 인사이트 리포트 | presentation | 외부 고객·시장 | 올해 봐야 할 이슈는 무엇인가 | 완결 문장 2–3문장(사실 → 시사) | 20–45 |
| `report_outline` | 보고서 구성안 | report | 고객 TF | 보고서 장마다 무엇을 넣는가 | 거버닝 없음, 장표마다 "넣을 내용"만 | 20–40 |
| `memo` | 요약·시사점 메모(A4) | report | 내부 보고 | 원문의 요지와 우리 시사점 | 개조식 `ㅇ` 단락 | 1–3쪽 |

- **문체 선택 규칙**: 외부에 나가는 자료(교육·세미나·제안·최종·리포트)는 v11의 완결 문장체, 프로젝트 내부 진행 자료(착수·주간·격주·월간·진단·벤치마킹)는 개조식을 기본으로 한다. 개조식 덱에서도 제안사가 하겠다고 약속하는 문장만 `~할 예정입니다`로 쓴다. 한 덱에서 두 문체를 섞지 않는다(레퍼런스 착수보고에서 섞인 사례가 있었지만 규칙으로 삼지 않는다).
- 글자 크기·색·좌표는 유형이 아니라 선택한 계열과 전달 방식(v17)이 정한다.

## 2. 유형별 목차 골격

장수는 기본값이고, 장당 비중은 레퍼런스 실측이다. 괄호는 교육·강의(블루) 템플릿 레이아웃, 다른 계열은 같은 구조를 [v18 §5](structured-slides-v18.md)로 옮긴다.

### 2.1 교육·강의 / 배포 교재

```
0  표지(01) → 목차(02b: 번호·장명·한 줄 설명·쪽) → 학습 목표 1장(03b)
Ⅰ 배경·제도 (전체의 25–30%)
   왜 지금인가(사실·수치, s03/03f) → 제도의 구조(s18 키워드 지도 / s05) → 핵심 관점 3–4개(s01)
   → 어디에 공시·적용하나(03c) → 참여·적용 동향(s03) → 다른 제도로의 확산(s09 연혁)
Ⅱ 요소별 요구사항·사례 (전체의 60–70%)
   [요소 k] 장 구분(02c: 이 장에서 답할 질문 3개 + 미니 목차)
   → 세부 항목마다 [요구사항 + 핵심 Focus 1장(s21)] + [사례 1–5장(s22), 해외 → 국내 순]
   → 요소 끝에 비교·판단 장표 1장(s19 / s17)
Ⅲ 우리 과제 (선택, 2차 교육·자문으로 분리 가능): 자가진단(s20) → 과제 목록(s05)
끝 핵심 정리(s23) → Key Questions 자가진단(s20) → Q&A·다음 단계(03b) → 맺음(04)
```

- 세부 항목 단위로만 늘리고 줄인다: 요구사항 1장은 필수, 사례는 1–5장. 사례만 늘려 장수를 채우지 않는다.
- 레퍼런스 교육자료에는 학습 목표·핵심 정리·Q&A 장표가 없었다. 이너젠 교육 덱은 이 3장을 반드시 넣는다(v13 "질문·답·근거" 모듈의 가시적 배치).
- 장 구분은 두 방식 중 하나로 통일한다: ① 목차 장표(02b)를 장 앞마다 다시 넣고 현재 장만 강조, ② 장 구분 장표(02c)에 질문 3개와 미니 목차. 장당 10장 이상이면 ②를 쓴다.

### 2.2 세미나·강연·발표

```
표지(제목·발표자·소속·행사·일자) → [개념 정의 또는 질문 1장] → 목차(3–4장, 쪽수)
장1 배경·개념 3–4장: 정의 → 리스크·수치(03f 큰 숫자 3개) → 왜 지금인가
장2 제도·동향 4–6장: 구조(s18) → 요구사항·비교표(s05) → 적용 시기(s16)
장3 분석·사례 5–8장: [사례] 태그 장표(s22) → 절차(s15) → 어려움·고려사항(s19)
장4 대응·준비 3–5장: 준비 단계(s15) → 로드맵(s08) → 결론 1장(s13 질문+방향 3개)
감사·연락처(04). Q&A 장표는 두지 않는다(질문은 자가진단 장표로 본문에 넣는다).
```

### 2.3 제안서·제안 발표

```
표지 → 고객 과제 한 문장(03b 결론 박스) → 제도·시장 근거(s03) → 핵심 쟁점 N개(s01 카드)
→ 목표와 범위 안/밖(03d) → 접근 방법·단계(s15 / s14 과업 구조) → 세부 수행 내용(03a 반복)
→ 산출물(03e) → 일정(간트, templates/charts/gantt_chart) → 수행 체계·인력(03d)
→ 이너젠 실적·차별점(03f) → 기대효과(s07 현행→개선→효과) → 다음 단계(Way forward, s13)
→ 첫 장의 과제 문장을 다시 보여 주는 맺음(04)
```

- 레퍼런스 제안형에는 수행 체계·투입 인력 장표가 없었다. 이너젠 제안서는 착수보고의 참여 인력 장표(역할·경력·담당 과업)를 미리 넣는다.
- 기대효과는 산식·근거가 있는 것만 숫자로 쓴다(v19 proposal 보존 조건).

### 2.4 착수보고

```
표지("착수보고"는 표지에만) → 목차(02b)
Ⅰ 프로젝트 개요 6–7장: 배경(고객 선언·목표) → 현황 As-Is(수치·갭, s03) → 대상·범위 정의(03d)
   → 업계 위치(s16 / s10) → 업무 범위(기간·대상·범위 3행, 03a) → 목적·기대효과(03d) → [참고] 시장 특성
Ⅱ 추진방안 5–6장: 과업 ①② 각각 접근 개요(s15) + 상세(03d) → 수행 일정 간트(마일스톤: 착수·중간·최종)
Ⅲ 데이터 수집 요청 1장: 요청물·기간·대상·형태·용도 + 담당·기한(s12 변형)
Ⅳ 관리방안 3–4장: 참여 인력(03d) → QA/QC·보안·성과품(s15) → 제안사 특장점(03f)
→ 결정 요청·다음 일정(s13 변형) → 맺음(04)
```

### 2.5 주간 진행보고

```
표지("W[n] 주간보고") → 목차 → Ⅰ 이번 주 맥락 2–3장(s03)
→ Ⅱ·Ⅲ 이번 주 주제 장(평행 구조: 개요 → 현황 표 → 이행 수단; 두 장은 같은 레이아웃 반복)
→ Ⅳ Wrap-up: 비교표(s19) → 일정·고객 판단 사항(s16 / s08)
→ 향후 추진 계획 1장: 분석 항목 ✓ 목록 + 추가 요청 항목 + 예상 일자(s12) → 맺음
```

### 2.6 격주 미팅 자료

```
표지 → 진행현황(기간) | 향후계획(기간) 2열표 1장(03d / s07 변형; 과업 행, 셀 머리 굵게, 일자 괄호)
→ 수행 일정 간트 1장(착수 때 간트 재사용, 현재 주차 표시)
→ 첨부1 직전 완료 산출물 전체 → 첨부2 차기 산출물 초안(와이어프레임)
```

- 본문은 2장으로 끝낸다. 회의록은 `일시·장소·주제·참석자 → 영역별 논의 → 결론·향후 일정` 순서이므로, 본문 2장의 과업 행과 회의록 영역이 1:1로 대응해야 한다.

### 2.7 월간 WG · 진행현황 보고

```
표지 → 과업 현황판 1장(s08 변형: 과업 × 상태 배지 完/진행 中/예정; 목차 겸용)
→ [교육 장] 동향·기준·핵심 Focus·사례(2.1의 Ⅰ장 축약, 5–15장)
→ [과업별 수행 현황 장] 분석 절차(s15) → 결과 시리즈(s03 / s05 반복) → 진단 절차 → Gap(s19)
→ [운영 현황 장] WG 운영 개요·교육 실적·상담 실적(실적표: 회차×일자×참석×주제×주요 의견)
→ 향후 추진 일정 간트 → APPENDIX(방법론·세부 결과)
```

### 2.8 진단·개선과제 도출

```
표지(부제 "대응체계 진단") → Framework 1–2장: 진단 관점·Key Questions·분석 프레임(s18 / s20)
→ [공통 프로세스] 기준 × 현황 × 개선과제 요약표 1–2장(s06; 과제 ①~④가 여러 기준 행을 묶음)
→ 과제 ①~④ 상세(s07 AS-IS→TO-BE, s15 프로세스, 지표표)
→ [영역별] 영역마다 "진단 1장(s06) + 실행과제 1장(s12) + [참고] 사례 1–3장(s22)" 세트
→ 개선과제 종합 1장(s05: 과제 × 용이성 × 효과성 × 추진여부 금년/차년/검토)
→ Appendix(분석 결과 갱신·방법론)
```

### 2.9 중간·최종보고

```
중간: 표지 → 요약(s01) → 진행 현황(s08) → 잠정 결과(s03·s05, "잠정" 표기) → 확인된 사실 vs 미확정(03d)
     → 이슈·리스크(03b) → 결정 요청(s13 변형) → 다음 단계(s15) → 맺음
최종: 표지("최종보고") → 목차 → Ⅰ 과업 개요(추진배경·목적 ①~③ + 과업 범위·추진계획 카드, s14)
     → 산출물 장마다 [운영 개요(실적표) → 결과(s03·s05) → 시사점(종합 → 개별, s13)]
     → 검증·한계(03b) → 잔여 과제·인계(s05) → 부록 → 맺음
```

### 2.10 경영진 요약(1–3장)

```
1 결과 요약: 접근 방법 3줄 + 매트릭스/핵심 표 + 중대 요인 번호 목록 + 우측 시사점 박스(결론 → 단, 단서 → 제안)
2 핵심 분석: 좌 분석 개요 라벨(대상·방법·도구) + 중앙 그림 + 우 해석 2줄(결론 / 단서) + 용어 각주
3 향후 계획: 기간 헤더 3열 × Task / Focus / 예시 행(s08)
```

### 2.11 벤치마킹

```
표지 → Approach(대상·방법·프레임) → 분석 주안점 Key Questions(s20) → 결과 Overview(레이더 + 영역별 Key Findings, s03)
→ 비교 히트맵(s10) → [n] 영역별 Gap표 ×N(s19: 항목 | 공시 현황 | 주요 Gap) → [Back-up] 사례(s22)
```

### 2.12 인사이트 리포트 · 보고서 구성안 · 요약 메모

- **인사이트 리포트**: 표지(시리즈·제목·발행월·조직) → 연락처/서문 → 목차(장·부제·쪽) → 배경 장(개념도 → 경쟁 구도 → 규제 연혁 → 지표 차트) → 이슈 개요 카드 1장(N≤7, s01) → 범주 매핑 1장(s05) → 이슈마다 3–4장[현황 → 제도 상세표 → 영향·전망] → Key Takeaways 2–3장(현황 요약 3열 → 이해관계자별 대응 방향) → 저자·연락처 → 면책.
- **보고서 구성안**: 보고서 목차를 장표로 펼치고 장표마다 "넣을 내용·출처·담당"만 적는다. 요소 디바이더에는 영문 태그라인 + 리드 단락 자리. 마지막은 요구항목 ↔ 페이지 매핑표(Index).
- **요약 메모(A4)**: 제목 「원문」(기관) 요약 및 시사점 + 【일자·부서】 → □ 원문 개요 → □ 주요 내용(ㅇ(키워드) 5–6개, `-` 세부, `*` 각주) → □ 시사점(ㅇ 2–3개, 명사형 종결) → 참고 표. 3쪽 이내.

## 4. 제목 체계

- 제목은 **주제 명사구** 10–30자. 결론·주장·질문을 넣지 않는다(결론은 거버닝, 질문은 자가진단 장표). 예외: 장 도입·마무리·관점 제시 장표의 질문형 제목, 세미나 6W 목차.
- 형식: 교육 `3. 장명 / 3-1 절명`, 보고 `Ⅰ. 장명 – 절명`, 세부 항목 `(a) 항목명 – 장표 유형`(장표 유형은 요구사항·사례·예시 3종), 두 개념을 묶을 때 `주제: 부제`.
- 사례 장표 제목에는 회사명·연번을 넣지 않는다. 회사·국가·산업은 본문의 사례 헤더(s22 `CASE_HEADER`)로 내린다.
- 같은 제목이 3장 이상 이어지면 `(n/N)`을 붙이고, 거버닝은 장마다 새로 쓴다. 제목을 거버닝에 복사하지 않는다.
- 제목 글자는 32px(24pt). 거버닝(24px)보다 크지만, 레퍼런스 교육자료처럼 제목을 거버닝보다 작게 두는 방식은 쓰지 않는다(이너젠 위계 v4 유지).

## 5. 거버닝 메시지

> 2026-10-14 v22: 거버닝은 **한 줄**로 고정한다(사용자 결정). 한글 기준 24px 38자·22px 40자·21.33px(16pt) 40자 이내. 두 줄 상한(75/85자)은 폐기. 템플릿 거버닝 영역과 `innergen_qaqc.py` G04가 한 줄을 검사한다.

### 5.1 역할과 위치

제목은 "무엇을 다루는가", 거버닝은 "그 내용에서 무엇이 중요한가", 본문은 "조건과 근거", 하단 결론 박스는 "어떻게 적용·행동하는가"다(v4). 거버닝은 거버닝 박스(48,70 / 944×80) 안 1문장, 최대 2줄. 본문 장표에는 거버닝을 비우지 않는다. 예외는 표지·목차·장 구분·맺음·경영진 요약(우측 시사점 박스로 대체)·보고서 구성안뿐이다.

### 5.4 숫자·기준시점·출처

- 거버닝에 핵심 수치 1–2개(연도, N%, N개, 범위)를 넣는다. 숫자가 전혀 없는 거버닝은 과업 서술로 떨어지기 쉽다.
- 기준시점은 `'[yy].[m]월 기준`, `[연도] 결산 기준`처럼 거버닝이나 표 우상단에 쓴다. 상태는 거버닝 끝 괄호로 `([월.일] 완료)`.
- 출처는 거버닝에 넣지 않고 하단 출처 줄에 쓴다(v16 형식: `출처: 기관, 「자료명」(발간연월), 기준연도·단위`). 예외는 조사 보고서명을 괄호로 한 번 인용하는 경우뿐이다.
- 거버닝의 수치·요건은 같은 장표 본문이나 레퍼런스에 근거가 있어야 한다(v11).

### 6.4 교육 장표의 학습 장치

- 요구사항 장표의 우측 `핵심 Focus`(정보 이용자 관점 2–4개)와 사례 장표의 `배울 점`이 학습 포인트다. 두 칸은 비우지 않는다.
- 질문은 `Key Questions` 자가진단 장표(s20)에 `~하고 있는가?` 형식 3–5문항, 완전성·품질·전달의 세 축으로 묶는다.
- 요소 개요(프레임워크)를 요소 시작마다 다시 보여 주고 현재 요소를 강조한다(02c 미니 목차).
- 용어 정의는 `[참고]` 박스나 각주로, 인용은 큰따옴표 + 발언자·출처로.

### 6.5 결론 박스·시사점

- 위치: 본문 아래 전폭 결론 박스(48–54px, `#EEF2FF` + 블루 막대) 또는 우측 시사점 열(1/3). 한 장표에 하나만.
- 내용: 거버닝을 반복하지 않고 "그래서 무엇을 할지"만. 외부 자료는 `~합니다`, 내부 자료는 `~필요 / ~검토`로 끝낸다.
- 경영진 요약과 조사·벤치마크 장표는 `Findings`(관찰)와 `Insights`(시사)를 섞지 않는다.
- 비교표의 결론은 마지막 행에 열별 1줄로 쓸 수 있다.

### 6.6 표 셀 문법

| 셀 | 문법 |
|---|---|
| 현황(당사) | 긍정 서술로 사실만. 판단은 Gap 열로 |
| Gap·진단 | `~부재 / ~미흡 / ~미제시 / ~불일치`로 끝나는 부정 서술 |
| 선도사·기준 | `~제시 / ~공시 / ~제공`으로 끝나는 긍정 동작명사 |
| 대응 현황 | `[완료 – 출처]`, `[추후 보완]`, `[확인 필요]` 태그 + 한 줄 |
| 과제 상태 | `금번 반영 / 계획 소통 / 향후 과제`, 추진여부 `금년 / 차년 / 검토` |
| 공시 여부 | `O / X` 한 글자, 색은 쓰지 않는다 |
| 상태 배지 | `완료 / 진행 중 / 예정`(날짜 괄호) |

### 6.7 출처·단위·기준시점

- 세 가지를 한 장표에 모두 둔다: 차트·표 우상단 `단위: …` 와 `'[yy].[m]월 기준`, 하단 출처 줄(v16 형식), 본문 보조 `* …` 각주.
- 분석 결과는 `출처: [툴·자료]를 바탕으로 이너젠 분석`으로 자체 분석임을 밝힌다. 예시 수치는 `예시`를 붙인다.
- 비율 차트는 분모와 표본(n)을 차트 안에 쓴다(v18 §1).

## 7. 시리즈·반복 장표

- 같은 구조를 반복할 때는 제목·프레임·범례·출처 위치를 고정하고, **거버닝 판단문 + 우상단 태그(기간·시나리오·대상) + 내비 강조**로만 변화를 보여 준다.
- 번호 체계: 영역 `[1]~[4]`, 과제 `①~⑩`(공통 과제 ①~④, 개별 과제 ⑤~), 분할 `(n/N)`, 세부 항목 `(a)(b)(c)`.
- 세트 단위로 묶는다: 교육 "요구사항 1 + 사례 1–5", 진단 "진단 1 + 실행과제 1 + [참고] 1–3", 시나리오 "보수·공격 2장 동형". 세트 간 장수 차이는 [참고] 장수로만 흡수한다.
- 11개 이상 반복되는 시리즈에는 좌측 세로 내비(s21)나 미니 목차(02c)를 둔다.
