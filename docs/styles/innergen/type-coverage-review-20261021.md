| 단계 | 보고유형 | 사업유형 | 확인 결과 |

자료 입력의 `memo`·`report_outline`은 PPT 본문 검사 대상 밖이다. 스타일의 `education`은 본문 검사에서 `lecture`로 해석한다. 자료 입력의 `ets`는 본문 검사에서 `regulatory` 별칭으로 해석한다.

## 이번 검토에서 바로잡은 판정

- `memo`·`report_outline`에 사업유형 B01 오류가 잘못 붙던 문제를 수정했다. 이 유형은 R00 정보 메시지만 남기고 R/B 필수 내용 검사를 건너뛴다.
- 알 수 없는 보고유형 ID가 정보 메시지만 남기고 통과하던 문제를 수정했다. 이제 R00 오류로 표시한다.
- 스타일 선택 화면의 축약된 4개 사업유형·4개 보고유형 목록을 기존 스타일 기준과 같은 9개·6개로 맞췄다.
- 자료 입력에 이미 이너젠 기준이 있던 LCA·제품 탄소발자국, ESG 평가 대응, 기후·ESG 교육, 기후테크·소셜벤처 4개 사업유형을 추가했다. 자료 요청 문구는 확인할 항목이며 수치나 사업 실적을 생성하지 않는다.

## 아직 남은 적용 범위

| 자료 입력 사업유형 | 현재 처리 | 남은 확인 |
|---|---|---|
| `ets` 배출권거래제 | 규제 대응 필수 내용으로 검사 | 할당·보유·거래·이행량 등 ETS 고유 항목은 별도 필수 규칙이 아님 |
| `esg_reporting` ESG·지속가능성 보고 | 전용 이너젠 사업유형 없음. B00 경고와 보고유형 공통 검사만 가능 | 보고 기준·중대성·지표 통제 등 전용 필수 규칙 필요 |
| `business_intro` 사업·서비스 소개 | 전용 이너젠 사업유형 없음. B00 경고와 보고유형 공통 검사만 가능 | 현재 제품·고객·화면·공개 승인 실적의 전용 규칙 필요. 이너캐리 디자인 참고 자료를 현재 사업 사실로 쓰지 않음 |
| `general` 기타·복합 업무 | 특정 사업 체크리스트에 자동 대응하지 않음 | 실제 과업을 먼저 분류하거나 프로젝트 전용 필수 항목을 명시 |

보고유형도 자료 입력 16개와 스타일 선택 6개가 서로 다른 목적의 분류다. `weekly`·`monthly`·`benchmark` 등은 본문 검사에는 있으나 스타일의 6개 보고 단계와 일대일로 대응하지 않는다. 제작 시 `deck_type`에 실제 보고 형태를 따로 기록해야 해당 필수 절을 검사한다. 현재는 두 필드 사이의 자동 대응표가 없다.

이 검사는 장표 제목·본문의 패턴과 레이아웃을 확인한다. 배출량 계산, 기간·단위의 일치, 법령 적용, 출처의 진위나 결과의 사업적 타당성을 증명하지 않는다. `innergen_qaqc.py`의 R/B/Q 검사는 SVG 덱 경로에 연결돼 있으며 원본 PPTX 양식 채우기 경로의 최종 검수를 대체하지 않는다.

## 권장 후속 작업

1. ETS, ESG 보고, 사업소개에서 실제 사용할 자료와 산출물 예시를 확보해 전용 필수 항목을 정의한다. `general`은 프로젝트별 목록을 명시한다.
2. 자료 입력의 16개 보고형태와 이너젠 스타일의 6개 보고 단계 사이에 명시적 연결 규칙을 둔다. 비슷한 이름만으로 자동 변환하지 않는다.
3. 대표 실제 덱으로 내용 검사의 과잉 경고·누락을 확인한다. 특히 숫자·단위·기간·법령은 원문과 별도로 대조한다.
