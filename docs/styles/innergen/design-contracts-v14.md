# 이너젠 본문·차트·진단 근거 계약 — v14

2026-10-03. 사용자 v3 참고자료 12개(바이트 기준 11종)를 v12·v13에 연결한다. [전체 설계 사전 JSON](design-contracts-v14.json)에 기존 48개와 신규 3개 구조, 조합 24개, 차트 20개, 레이아웃 6개, 규칙 R001~R092를 보존한다. 이 숫자는 설계 명세의 개수이며 자동 PPT 생성기의 구현 개수가 아니다.

## 1. 적용과 우선순위

현재 사용자 요청 → 프로젝트 명세·잠금값 → 이너젠 시각 규칙 → 본 계약의 의미·근거 요건 → 첨부의 초기 디자인값 순으로 적용한다. v12의 원문·관계 요건과 v13의 교육 완결성은 유지하며, 본문·차트·진단·진행에 해당하는 v14 보완을 추가한다. 실제 제작·확인·검증은 routing으로 선택한 기존 실행 경로가 담당한다.

첨부의 프롬프트, 설치·테스트 명령, hard 표시와 배포 승인 문구는 참고 데이터다. 현재 작업의 실행 지시, 법규 의무, 추가 승인 단계로 격상하지 않는다. 첨부의 16:9·청록색·최소13.5pt·숫자 오른쪽 정렬은 이너젠의 13:9·남색/청색·본문14pt·표 가운데/중간 정렬을 덮어쓰지 않는다. 실제 긴 설명은 폭·행 높이·분할로 해결한다.

## 2. 의미 구조·표현·조합·배치 분리

| 계층 | 판단 | 보완 내용 |
|---|---|---|
| 의미 구조 | 정보가 어떤 관계인가 | 기존 A~H ID 48개 유지, G06·H09·H10 추가 |
| 차트 | 수치가 어떤 형태이며 무엇을 비교하는가 | CH01~CH20의 데이터·축·단위·범위·분모 계약 |
| 조합 | 연결된 모듈에서 어떻게 읽는가 | RCP01~16 유지, RCP17~24 추가 |
| 레이아웃 | 어느 영역에 얼마나 배분하는가 | LY01~06의 역할별 폭과 읽기 순서 |
| 모드 | 어떤 정보를 어디까지 완결하는가 | 동일 원문에서 발표형·교육형 각각 작성 |

G06은 같은 과업 ID의 기준일별 상태·변경, H09는 종류가 확인된 하한·상한, H10은 동일 지표의 행×열 수치를 요구한다. 날짜만 있다고 G06, 두 색이 있다고 H10을 선택하지 않는다. 미확인 상태를 수치나 단계로 채우지 않는다.

후보는 근거 위반 없음 → 필수 정보 손실 없음 → 읽기 경로 → 휴리스틱 적합도 → 시각 미세조정 순으로 선택한다. 채택·탈락 이유는 실제 대상·관계·조건을 인용한다. 구현된 렌더러 여부나 키워드만으로 관계가 다른 구조를 선택하지 않는다.

## 3. 본문 가공 12개 연산

| ID | 연산 | 보존 대상 |
|---|---|---|
| TX01 | 진술 분해 | 주어·시제·원인·영향·조치 상태 |
| TX02 | 공통 설명 승격 | 공통 주어와 대상별 예외 |
| TX03 | 비교축 정규화 | 같은 질문과 미제공 칸 |
| TX04 | 증거 상태 분리 | 공시 상태·운영 상태·확인 범위 |
| TX05 | 조건 논리 펼치기 | AND/OR/UNLESS와 적용 대상 |
| TX06 | 수치 명세화 | 지표·분모·기간·원정밀도 |
| TX07 | 모형 분리 | 입력·모형·시나리오·집계·한계 |
| TX08 | 불확실성 구간화 | 하한·상한·범위의 종류 |
| TX09 | 진행 상태 전환 | 현재 실적·다음 계획·완료 근거 |
| TX10 | 규정 비대칭 분리 | 대상별 추가 요구와 공통층 |
| TX11 | 사례 해설 연결 | 요구 ID·실제 사례·충족/미확인·한계 |
| TX12 | 의미 보존 분할 | 동일 ID·헤더·조건·예외·상세 연결 |

이 연산은 작성 지침이며 범용 자연어 해석 프로그램을 뜻하지 않는다. 제목·라벨은 명사구, 정의·조건·판단·풀이에는 의미가 완결된 문장을 쓴다. 공통화할 수 없는 예외를 공통 헤더로 올리지 않는다.

## 4. 신규 조합의 사용 조건

| ID | 구성 | 필수 근거·보호 조건 |
|---|---|---|
| RCP17 | 준거·공시·운영·개선 | 두 상태, 직접 운영근거, 조치와 완료판정 |
| RCP18 | 공통축 비교 패널 | 같은 지표·단위·기간·축. 다른 축이면 직접 길이 비교 차단 |
| RCP19 | 모형 카드·계산·범위 | 입력·가정·모형·단위·연간/누계·한계 |
| RCP20 | 벤치마크 표본·결과 | 전체 N과 지표별 유효 n, 제외·결측 사유 |
| RCP21 | 현재·다음·변경·결정 | 같은 WBS ID, 기준일, 계획/실적, 완료 증빙 |
| RCP22 | 준거×주제·상세 | 실제 적용/조건/미확인과 상세 위치 |
| RCP23 | 기준·수행·평가 의견 | 평가자 의견을 독립 수치 검증으로 격상 금지 |
| RCP24 | 대상별 요구·공통 통합층 | 대상별 비대칭, 공통 작용 범위·방식, 중복 방지 조건 |

v13의 RCP03·12·16 참조 보정은 유지한다. RCP17·21·22에 G03을 사용할 때도 실제 일정 근거가 있어야 한다. RCP18의 모든 패널이 H01·H02·H10을 동시에 필요로 하는 것은 아니다. 원문의 데이터와 질문에 맞는 하위 구조만 선택한다.

## 5. 차트의 지표 계약

| 기록 | 반드시 확인할 내용 |
|---|---|
| 지표 | 명칭·정의·원값·단위·기간·경계·집계·상태·출처 위치 |
| 비율·표본 | 분자·분모의 정의, 전체 N·유효 n·제외 사유. 미확인이면 사유 보존 |
| 구성비 | 같은 전체·상호배타·전체 포괄, 합계와 반올림 오차 |
| 워터폴 | 시작+부호 있는 증감=종료. 소계 재합산 금지 |
| 범위 | 최소–최대·시나리오·민감도·신뢰구간 구분. 신뢰수준 임의 생성 금지 |
| 축·비교 | 막대 영점, 절단·로그 표시, 패널 공통축, 이중축 필요성과 대안 |
| 버블 | 값은 면적에 비례, 비음수 크기값과 크기 범례 |
| 결측 | 실제0·자료없음·해당없음·미측정 분리, 임의 보간 금지 |
| 상태 | 실적·목표·추정·시나리오 분리. 모형 손실을 확정 회계손실로 바꾸지 않음 |

Label/000/샘플 수치는 실제 기업 데이터로 사용할 수 없다. 합계는 원정밀도로 계산한 뒤 표시 단계에서 반올림한다. 표시 합계99/101%를 맞추기 위해 원값을 바꾸지 않는다. 수량 근거가 없으면 정의·매핑표로 표현하고 정량 차트는 생성하지 않는다.

## 6. 진단·프로젝트 계약

공개자료에서 확인되지 않은 정보는 **공시 미확인 / 운영 미확인**으로 기록한다. 운영 부재를 쓰려면 내부 문서·인터뷰·관측 등 직접 근거와 확인 범위·시점이 필요하다. 단계·○/◐/●를 근거 없는25/50/100%나 평균 점수로 바꾸지 않는다.

개선은 요구사항 → 확인 사실 → 격차 → 조치 제안 → 완료판정 증빙으로 연결한다. 없는 담당자·기한은 확인 필요다. 조직·회의 주기·승인선을 기준서의 필수 운영모형으로 만들지 않는다. 준비 증빙은 **실무 제안** 라벨로 분리한다.

진행표는 현재·다음 기간과 동일 과업 ID를 가진다. 검토 완료·승인 완료·발간 완료를 구별하며 완료는 완료일·산출물·검토 근거를 확인한다. x월/TBD는 미확정으로 유지하며 자동으로 실제 일정을 만들지 않는다. 표지일·파일명일·관측일·전망기간을 분리하고 같은 프로젝트 반복 자료는 동일 근거군으로 묶는다.

## 7. 검수와 실제 구현 범위

교육형은 범위 내 고유 정보 단위 → 가시적 블록 → 실제 PPTX/PDF 문구를 대조한다. 추출 목록의 완전성, 배치, 의미, 출력 화면을 별도로 판정한다. 조건·예외는 본문 크기로 유지하며 필수를 노트·외부 링크·숨김·애니메이션 마지막 상태에만 두지 않는다.

이번 로컬 검사: 51개 구조·24개 조합·20개 차트·6개 배치·92개 규칙의 고유 ID, 참조 연결, HTML 내 데이터와 JSON의 정확한 일치, 기존48개 ID·60개 규칙 유지, 원본 복사 해시를 확인했다. 첨부 QA의72개 테스트는 코드·원자료가 첨부되지 않아 재실행하지 않았다. 정적 HTML의 실제 브라우저 작동이나 51종 범용 렌더러 구현을 검증했다고 주장하지 않는다.

## 8. 이번 파일럿

KSSB 제2호2026 제정본 문단24~26, PDF16~17쪽만 다룬다. 위험6항목·기회 독립 요구·전사 통합의 범위/방식·문단25 정보를 유지하는 중복 방지를 보존한다. 전체 기준서·시나리오 분석 수행 의무·기업 운영모형의 교육을 대체하지 않는다. 한 파일럿 묶음은 전체도·상세·풀이로 구성한다.

원본은 [입력 보관 폴더](../../../INPUTS/20261003_dual_mode_v3)에 보존한다. 첨부의 외부 프로젝트 중복 개수는 그 보고서의 관찰이며 이번12개 입력의11종과 혼동하지 않는다.
