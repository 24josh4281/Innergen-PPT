# 이너젠 본문 도식 후보·목차 자동 생성 v33 (2026-10-21)

본문 내용이 정해져도 그리는 방법은 여럿이다. 5단계 수행 방법은 셰브런·세로 번호 단계·시간축으로, 병렬 과제 4개는 카드·표·허브로 그릴 수 있다. 이 문서는 (1) 어떤 장표에 후보를 만들지, (2) 내용에서 관계를 어떻게 읽고 후보 3개를 어떻게 고르는지, (3) 목차를 본문에서 자동으로 만드는 방법을 정한다. 관계 ↔ 도식 원칙은 [content-principles-v32.md](content-principles-v32.md) §6을 따른다.

## 1. 흐름

여러 도식 후보는 **선택 기능**이다. 목차 단계에서 "여러 도식 후보 보기"를 체크한 장·장표만 후보 2–3개를 만들고, 체크하지 않은 장표는 지금처럼 도식 1개로 쓴다.

| 단계 | 명령 | 산출물 |
|---|---|---|
| ① 목차 체크리스트 | `toc_builder.py build`가 목차를 만들 때 함께 쓴다. 따로 만들 때는 `content_diagrams.py select <project> [--check Ⅲ,P11]` | `analysis/diagram_select.md` |
| ② 체크 | 사용자(또는 채팅에서 사용자가 말한 대로 작성 AI)가 장 줄이나 장표 줄에 `[x]`. 장을 체크하면 그 장의 본문 장표 전체. `★`는 중요도 추천이고 체크는 아니다 | 같은 파일 |
| ③ 대상 확정 | `content_diagrams.py plan <project>` — 체크한 장표만 나열(체크가 없으면 0장). `--auto`는 체크 대신 중요도 상위 약 25% | `analysis/diagram_plan.md`·`.json` |
| ④ 내용 정리 | 새 장표: 계획표에서 JSON 작성 / 그린 장표: `content_diagrams.py extract <slide.svg>`로 초안을 뽑아 다듬기 | `analysis/diagram_variants/pNN/content.json` |
| ⑤ 후보 3개 | 템플릿 덱: `content_diagrams.py build content.json --family <family> -o analysis/diagram_variants/pNN` / 이미 그린 덱: `--base svg_output/NN_이름.svg`를 더하면 그 장표의 머리·거버닝·출처·꼬리말을 그대로 두고 본문만 다시 그린다(색·글자 크기는 프로젝트 `spec_lock.md`) | `v1_*.svg`–`v3_*.svg`, `variants.html`(나란히 비교), `variants.json` |
| ⑥ 고르기 | 작성 AI가 추천(v1)을 넣는다. 원본은 `pNN/original.svg`로 남긴다. 바꿀 때 `content_diagrams.py pick <dir> <번호|도식명> -o svg_output/NN_이름.svg` | 덱 장표 |
| ⑦ 검사 | `svg_quality_checker.py` → `innergen_qaqc.py` → `innergen_story_check.py` | 기존 보고서 |

- 체크한 장표도 사용자에게 매번 고르게 하지 않는다. 추천 후보로 덱을 먼저 완성하고 채팅에서 "P11은 셰브런으로 넣었고 세로 단계·시간축 후보가 있습니다"처럼 알린다.
- 채팅으로 목차를 확인할 때 "여러 도식 후보를 볼 장이 있으면 말씀해 주세요(예: Ⅲ장, P11)"를 한 줄 붙이고, 답이 없으면 체크 없이 진행한다.
- 원문에 없는 항목·수치를 후보를 채우려고 만들지 않는다. JSON의 모든 문장은 계획표나 원문에 있어야 한다.

## 2. 내용 JSON

```json
{
  "title": "단계별 수행 방법", "section": "Ⅳ. 수행·검증", "page": 11,
  "governing": "대표 유형으로 한 주기를 시범 검증한 뒤 같은 방법을 전 대상에 확산합니다",
  "source": "출처: …", "relation": "auto",
  "conclusion": "시범 결과가 범위·공수 가정을 바꾸면 확산 전에 조정 승인합니다",
  "items": [{"label": "진단", "period": "WP1·2", "desc": "…"}, …]
}
```

| 필드 | 쓰임 |
|---|---|
| `items[].label` | 도식 안 라벨. 2–6어절 명사구(원칙 §6.2) |
| `items[].desc` | 라벨 아래 설명 1–2줄 |
| `out`·`done` | `desc` 대신 쓰면 칸을 '산출물'·'완료 기준' 두 줄로 나눈다(셰브런). 산출물과 완료 조건이 한 문단에 섞이지 않게 한다 |
| `gate` | 이 단계 **다음**에 오는 판단 지점(예: "범위·공수 재승인"). 단계 사이에 강조색 마커 하나만 두고 셰브런은 한 톤으로 맞춘다 |
| `client` | 단계별 고객 몫. 셰브런 아래 '고객 결정' 행으로 따로 두고 단계 끝 승인 마커를 붙인다(`gate`가 있으면 마커는 게이트 하나만). 행 이름은 `client_label`(예: '고객 역할' — 결정이 아니라 제공·회신이 섞일 때) |

칸 안 줄바꿈: 글줄은 길이가 고르게 나뉘어 한 단어만 남는 줄을 만들지 않는다. 의미 단위로 끊어야 할 곳은 값 안에 `
`을 넣는다(예: `"승인 정보팩
매뉴얼
차년도 계획"`). 5–6단계 셰브런은 칸이 좁으므로 한 줄을 명사구 하나로 쓴다.

글자 화살표 줄(`A → B → C`)이 남은 장표는 `content_diagrams.py arrows <slide.svg> --group <그룹 id> [--accent "고객 승인"]`으로 같은 자리에 셰브런 단계 띠를 그린다. 색 띠 하나에 그 줄만 있으면 띠 자체가 단계가 되고, 패널 안에 있으면 아래 글줄과 패널을 띠 높이만큼 내린다. `--accent`는 판단 지점 한 곳만 채운다.
| `period` | 시점·단계 표시 → 순서 관계, 시간축 후보 |
| `group` | 상위 묶음 → 위계 관계(트리·층·묶음 표) |
| `value`·`unit` | 수치 → 규모 관계(막대·큰 숫자·표) |
| `x`·`y` + `axes` | 두 축 점수 → 매트릭스(2×2·점수 막대·표) |
| `columns` + `a`·`b` | 현행·목표 같은 두 열 → 비교 관계 |
| `conclusion` | 아래 결론 띠 한 문장(원칙 §6.2 "도식은 결론 띠로 닫는다") |
| `relation` | `auto`면 아래 §3.2로 추론, 아니면 지정 |

`content_diagrams.py example <관계>`가 관계별 예시를 출력한다.

## 3. 규칙

### 3.1 중요도 추천(`★`, `plan --auto`)

대상은 목차 체크로 정한다. 아래 점수는 체크리스트의 `★` 표시와 `plan --auto`에만 쓴다. 본문 장표마다 점수를 매겨 상위 약 25%(최소 2장, 최대 `--max` 6장)에 `★`를 단다.

| 신호 | 점수 |
|---|---|
| 순서·흐름을 글로만 표현(번호 줄·`→`·`n–m주`·`WPn`·`n단계`가 2줄 이상이고 전용 도식 레이아웃이 아님) | +1 + 줄 수/2 (최대 +5) |
| 본문 6줄 이상(4–5줄은 +1) | +3 |
| 장의 첫 장표 | +2 |
| 거버닝에 수치 | +2 |
| 핵심 주제어(전략·방안·로드맵·절차·과제·결과·시사점 등) | +2 |
| 마무리 3장 | +2 |
| 이미 전용 도식(gantt·matrix·waterfall·chart 등) | −2 |

### 3.2 관계 추론과 후보 순서

| 데이터 표지 | 관계 | 후보(앞이 추천) |
|---|---|---|
| 모든 항목에 `x`·`y` | 2축 분류 | 2×2 매트릭스 → 점수 막대(축1 × 축2) → 표 |
| `columns` + `a`·`b` | 비교 | 현행 → 목표 2열 → 표 → 카드(a → b) |
| 모든 항목에 `value` | 규모 | 가로 막대 → 큰 숫자 카드(4개 이하) → 표 |
| 모든 항목에 `group` | 위계 | 트리 → 층 구조 → 묶음 표 |
| `period` 절반 이상, 번호 라벨, 제목·거버닝의 단계·절차·로드맵 | 순서 | 셰브런(3–6) → 세로 번호 단계 → 시간축 |
| 제목·거버닝의 원인·영향·이어져·초래(5개 이하) | 인과 | 원인 → 영향 → 결과 체인 → 세로 단계 → 표 |
| 위 표지 없음 | 병렬 | 카드 → 허브(중심 개념 + 요소) → 표 |

- 설명이 길면(항목당 평균 45자 초과) 글 칸이 넓은 도식을 앞으로 올린다: 순서는 세로 단계, 병렬은 표.
- 항목 수가 도식 범위를 벗어나면 그 도식은 뺀다(셰브런 3–6, 카드 2–6, 큰 숫자 2–4, 2열 비교 6행 이하 등). 설명이 없는 항목은 카드를 만들지 않는다.
- 그린 결과에서 글자가 잘린 후보는 잘리지 않은 후보 뒤로 보낸다. 경고는 `variants.html`과 콘솔에 남는다.
- 모든 후보는 패밀리 `03a_content.svg` 틀(제목·거버닝·출처·꼬리말)에 들어가고, 도형은 `rect`·`polygon`·`line`, 글자는 `text`라 PPTX에서 편집할 수 있다. 상자 안 번호·라벨·설명은 한 묶음으로 세로 가운데 정렬한다.

### 3.3 고르는 기준(검토자·사용자)

1. 거버닝의 판단이 도식만 봐도 보이는가(강조 한 곳).
2. 관계와 맞는가(순서 없는 내용에 화살표 금지, 축 이름 없는 매트릭스 금지).
3. 앞뒤 장표와 같은 골격을 쓰는가(같은 프레임은 같은 도식으로 반복).
4. 글자가 잘리지 않는가.

`innergen_story_check.py`는 골라 넣은 장표의 `data-content-diagram`을 읽어 N30(관계 표지)을 같은 기준으로 검사한다.

## 5. 목차 자동 생성 (`toc_builder.py`)

```bash
python3 .claude/skills/ppt-master/scripts/toc_builder.py chapters projects/<p>            # 장·절·쪽 확인
python3 .claude/skills/ppt-master/scripts/toc_builder.py build projects/<p> --family <family> \
    -o projects/<p>/svg_output/02_목차.svg --lead "이 덱의 답 한 문장" [--dividers projects/<p>/analysis/toc_dividers]
```

- 장은 본문 제목의 장 표시(`Ⅱ. 장명 – 절명`, `Ⅱ. 장명 / 절명`), 없으면 꼬리말 장 라벨(손으로 그린 장표는 아래쪽 왼편 `고객 · 장명`), 계획 JSON은 `chapter` 필드에서 읽는다. 장 표시가 없는 앞쪽 도입 장표는 목차에서 뺀다.
- 장 번호는 Ⅰ, Ⅱ …, 설명은 절 이름을 ` · `로 44자까지 잇고 넘치면 `등`, 쪽은 `5–10쪽`. 간지 장표는 다음 장 범위에 넣는다.
- 장 수에 맞춰 `02b_toc_pages_3/4/5`(6장은 `02b_toc_pages`)를 고르고, 2장이면 3칸 틀에서 빈 칸을 지운다.
- `--dividers`는 장마다 현재 장 번호 원을 강조색으로, 나머지 장명·쪽을 회색으로 바꾼 목차를 만든다(원칙 §3.3, 본문 16장 이상). 해당 장 첫 쪽 앞에 넣는다.
- 검사: 장 수 2–6(ERROR), 장명 20자 초과·문장형·번호 역순·떨어진 같은 장(WARN). `--lead`가 없으면 목차 거버닝이 비었다고 경고한다.

## 7. 한계
