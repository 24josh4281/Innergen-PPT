# 이너젠 본문 구조화·도식화 작성 규칙 — v12

2026-10-03. 제공된 컨설팅 장표 자료 6개를 검토해 이너젠의 본문 작성 규칙을 보완한 버전이다. 원문의 의미를 먼저 정리하고 표·도식을 선택한다. 첨부 자료의 48개 유형은 자체 제안 분류이며 컨설팅사의 공식 규정이나 이너젠 원본의 관측 통계가 아니다.

## 1. 적용 범위와 유지할 디자인

| 항목 | 적용 |
|---|---|
| 대상 | 새 이너젠 장표의 본문 작성, 재구성을 허용한 기존 본문의 개선 |
| 기존 문구 보존 요청 | 근거·관계·누락만 점검. 문구·순서·장수 변경은 요청 범위에서 수행 |
| 이번 보완 | 독자 질문, 원문 분해, 묶음, 행·열·노드, 구조 선택, 문구 편집, 손실 검토 |
| 디자인 | 프로젝트에서 선택한 이너젠 변형·확정 색상·글꼴·크기·로고 유지 |
| 최신 교육 프로필 | 소개자료 v4.2 기반이면 v9/v10 시각 규칙과 v11 거버닝 원칙 적용 |
| 실행 | 저장소의 routing과 선택된 제작 경로가 확인·생성·검사·내보내기 담당 |

이 문서와 [구조 사전](design-body-v12.json)은 작성 참고자료다. 프로젝트 `spec_lock.md`, 첨부 패키지의 semantic IR 스키마, 자동 선택 프로그램을 대신하지 않는다. [재사용 프롬프트](prompt-body-v12.md)와 [예시](body-examples-v12.md)를 함께 사용할 수 있다.

첨부의 16:9·청록 테마, 4px 배수 글자 크기, 일반적인 글자 수 예산을 이너젠의 확정값에 덮어쓰지 않는다. 다이어그램 라이브러리에서는 관계·노드·연결선 관례를 참고하고 색상·글꼴·크기·페이지 영역은 프로젝트 명세를 따른다.

## 2. 장표마다 답할 질문 하나

**작성 순서**: 독자 질문 → 원문 진술 → 관계 → 본문 → 거버닝 → 하단 점검. 제목의 번호나 원하는 도형 수로 본문을 결정하지 않는다.

| 독자 질문 | 본문이 제공할 답 | 우선 검토 구조 |
|---|---|---|
| 무엇을 알아야 하는가 | 같은 분류축의 개념과 구체 설명 | A01·A04 |
| 무엇이 다른가 | 동일 기준으로 확인한 차이 | B01·B02·B06 |
| 무엇이 부족한가 | 기준·증빙·격차·보완 행동 | C02 |
| 왜 발생하고 어떻게 대응하는가 | 문제·원인·영향·조치의 대응 | C01·F01 |
| 어떤 경우에 적용하는가 | 조건·분기 결과·예외 후 잔여 사항 | D04·B06 |
| 어떻게 수행하는가 | 확인된 순서·활동·산출물 | D01·D02 |
| 누가 무엇을 수행·인계하는가 | 실제 역할·권한·인계 | D03·E02·E06 |
| 어떤 범위에 포함되는가 | 경계·분류·포함·제외 근거 | A05·E01 |
| 무엇에 어떤 영향을 주는가 | 동인·사업경로·결과의 근거 | F02·F03 |
| 언제 무엇을 추진하는가 | 사건 또는 계획의 기간·상태 | G01·G02·G03 |
| 수치가 얼마나 다른가 | 지표·단위·기간·범위가 같은 값 | H01~H07 |

한 장에서 서로 독립된 질문 두 개를 상세히 답해야 하면 개요+상세 또는 두 장으로 분리한다. 장수 제한이 있으면 근거 있는 요약과 별도 상세 자료를 연결하고, 핵심 조건을 임의로 제거하지 않는다.

## 3. 요약 전에 원문을 분해

**진술 단위**: 한 단위에 하나의 주체·상태·핵심 서술을 둔다. 같은 문장에 현황·영향·계획이 있으면 나눈다. 원문·출처는 보존한다.

| 필드 | 기록할 내용 | 실무 주의점 |
|---|---|---|
| 근거 ID | `C01`처럼 프로젝트 안에서 고유한 ID | 페이지 번호와 분리. 같은 문장을 나눠도 원문 연결 유지 |
| 원문·위치 | 문서명, 실제 페이지 또는 절·표·셀·문단 | 위치를 추정하지 않음. PDF가 없으면 페이지를 만들지 않음 |
| 주체·대상 | 회사·법인·사업장·담당자·지표 | 서로 다른 조직 경계를 공통 주어로 합치지 않음 |
| 핵심 서술 | 무엇이 확인·계획·요구됐는가 | 업무 활동과 기대 효과를 구분 |
| 상태 | 사실 진술 / 관찰 / 계획 / 목표 / 가정 / 제안 | 사실 진술은 원문이 그렇게 주장한다는 뜻. 독립 검증 완료와 구분 |
| 판단 근거 | 명시적 원문 / 조건부 원문 / 근거에서 도출한 판단 | 도출 판단은 사용한 기준과 증빙을 함께 기록 |
| 수치 맥락 | 값·단위·분모·기준연도·기간·경계·방법 | 값만 남겨 다른 기준의 수치와 비교하지 않음 |
| 적용 조건 | 대상, AND/OR, 부정, 예외, 기간, 가능성 | 판단을 바꾸는 조건은 핵심 본문에 유지 |
| 권위·시점 | 법령·기준 / 내부 방침 / 원문 계획 / 실무 제안, 자료 버전·기준일 | 과거 자료를 현재 의무로 단정하지 않음 |

**제안 처리**: 원문에 없는 관리장치·담당자·일정·효익을 새로 권고할 수는 있다. `실무 제안`으로 분리하고 근거가 되는 문제를 연결한다. 제안을 원문 사실·확정 계획·새 법적 의무로 바꾸지 않는다.

**불명확 상태**: `확인 필요`, `자료 미제시`, `해당 없음`, `없음`, `0`을 구분한다. 자료가 첨부되지 않았다는 사실만으로 미운영·누락 공시를 판정하지 않는다. 동일 목표의 연도가 다르면 양쪽을 보존하고 충돌로 기록한다.

## 4. 같은 질문·같은 수준으로 묶기

| 작업 | 작성 규칙 | 점검 |
|---|---|---|
| 묶음 기준 | 같은 질문에 답하는 항목끼리 묶음 | 비슷한 키워드만으로 합치지 않았는가 |
| 상위 라벨 | 아래 항목들의 공통 대상·역할을 표현 | `기타`, `고도화`만으로 내용을 감추지 않았는가 |
| 형제 항목 | 영역끼리, 활동끼리, 지표끼리 동일 수준 | `거버넌스 / Scope 3 / 감축성과`처럼 축이 섞이지 않았는가 |
| 공통 주어·범위 | 모든 하위 항목에 실제로 공통일 때 머리글로 이동 | 예외 행에는 다른 범위를 남겼는가 |
| 분류 중첩 | 주분류와 교차 태그 또는 매핑으로 유지 | 보기 좋게 하려고 다대다 관계를 일대일로 바꾸지 않았는가 |
| 추상화 | 상위 개요는 요약, 상세는 구체 대상·조건·증빙 | `관리 강화` 아래 실제 수단이 있는가 |

**구조를 보여주는 본문**: 소제목 아래에 소제목을 반복하지 않는다. `자료 수집` 아래에는 원문에 있는 `활동량 취합 / 증빙 확보`를 배치한다. 원문에 산출물이 없으면 `검증 보고서` 같은 결과물을 임의로 추가하지 않는다.

## 5. 표의 행·열을 정하는 규칙

**행키**: 한 행은 하나의 사업장·문제·요구사항·비교기준·시점 중 하나를 나타낸다. 행마다 단위를 바꾸지 않는다. 모든 열이 그 행키의 속성 또는 관계를 설명하도록 한다.

| 원문의 반복 형태 | 행·열 설계 | 주의 |
|---|---|---|
| 사업장별 자료·오류·조치 | 행=사업장, 열=자료·오류·조치 | 서로 다른 사업장의 조치를 같은 행에 배치하지 않음 |
| 대상은 적고 비교 속성은 많음 | 행=공통 비교기준, 열=대상 | 적용기간·범위·방법 차이는 비교의 제한으로 명시 |
| 대상은 많고 속성은 적음 | 행=대상, 열=속성 | 대상 묶음별 분할 시 기준열 반복 |
| 문제마다 원인·영향·대응 반복 | 행=문제, 열=원인·영향·조치 | 원인은 문제의 원인, 조치는 해당 문제의 대응이어야 함 |
| 기준과 증빙 대응 | 행=요구사항, 열=증빙·판단·격차·보완 | 요구사항의 버전·적용대상·의무/권고 구분 |
| 항목별 속성이 서로 다름 | 사례별 같은 최소 항목 또는 개별 설명표 | 비교 불가능한 셀을 억지로 채우지 않음 |
| 여러 표를 연결 | 공통 행 ID를 먼저 정하고 높이 정렬 | 눈높이가 같다고 같은 항목으로 간주하지 않음 |

중요한 적용 조건·담당·기간을 독립 비교해야 하면 열을 분리한다. 독립 비교가 필요 없는 보조 설명은 같은 구획의 주석으로 둔다. 병합 셀은 표현용으로만 사용하고 근거 기록에는 상위 분류·범위를 각 행에 남긴다.

## 6. 48개 구조 선택: 근거 충족이 미적 선호보다 우선

[JSON 사전](design-body-v12.json)의 A~H·48개 ID를 구조 탐색에 사용한다. ID는 본문 형식의 참고 코드이며 PPTX 마스터·레이아웃 ID가 아니다. 파일의 `required_evidence`, `slot_policy`, `do_not_use_when`, `innergen_adaptation`을 함께 확인한다.

| 관계 | 최소 필요한 근거 | 근거가 부족할 때 |
|---|---|---|
| 병렬 | 같은 분류축의 독립 항목 | 확인된 항목 표. 순서 화살표 생략 |
| 비교 | 공통 비교기준·동일 의미의 값·차이의 조건 | 차이·미확인 범위를 표시한 현황표 |
| 진단 | 기준과 관찰 증빙의 대응, 판단 논리 | 확인 현황·추가 확인 항목 표 |
| 순서 | 무엇 다음에 무엇인지 명시 | 병렬 활동표. 번호만으로 단계 판정 금지 |
| 조건 분기 | 판정 질문·조건·각 결과 | 공통사항/예외사항 표. 미확인 경로 표시 |
| 포함·분류 | 부모·자식 또는 포함·제외 기준 | 항목·범위·근거 표 |
| 보고·승인 | 공식 방향·행위·권한 근거 | 협업 역할표. 상하 보고선 생성 금지 |
| 인과·영향 | 연결마다 경로·조건·원문 주장 또는 분석 근거 | 병렬 관찰 또는 영향 가정표. 점선도 근거 부족을 해결하지 못함 |
| 시간·계획 | 사건 날짜 또는 활동 기간·미래 상태 | 기간 확인 필요의 계획표 |
| 정량 | 지표·단위·기간·범위·방법과 유형별 추가 조건 | 값·범위를 보존한 자료표. 크기로 차이를 암시하지 않음 |

**선택 절차**: 부적합 구조를 먼저 제외 → 남은 후보 최대 3개 비교 → 질문 적합성·중요 정보 보존·밀도·편집 가능성으로 선택. 코드에서 계산하지 않은 적합도 점수나 확률을 꾸미지 않는다. 간단한 표가 관계를 충분히 전달하면 표를 선택한다. 구조의 필수 관계가 없으면 확인 필요 셀을 채웠다는 이유만으로 그 도식을 완성하지 않는다.

**관계 변경**: 문구를 바꾸면서 순서·인과·보고가 사라졌으면 구조도 다시 선택한다. 상자 모양만 바꾸고 의미 슬롯을 그대로 두지 않는다.

## 7. 주요 구조별 본문 작성 레시피

| 구조 | 본문 구성 | 꼭 유지할 정보·경계 |
|---|---|---|
| A01 병렬 주제 | 같은 수준의 주제 + 구체 설명·근거 | 독립 항목 간 화살표 없음. 세 칸 강제 금지 |
| A04 정의표 | 용어 / 원문 정의 / 적용범위·예외 | 비슷한 용어를 같은 뜻으로 합치지 않음 |
| A05 범위도 | 전체 경계 + 포함/제외 항목 + 기준 | 경계는 근거로 판정. Scope 범주와 조직경계 구분 |
| B01 비교표 | 공통 기준 / A / B / 필요한 제한 | 범위가 다르면 제한 표시. 우열은 별도 기준 필요 |
| B02 현재·지향 | 구분축 / 현재 상태 / 지향 상태 | 지향 상태에 계획·목표·제안 표시. 조치를 상태와 혼동하지 않음 |
| B06 공통·예외 | 공통 적용 / 예외 조건 / 예외 후 잔여 사항 | 예외 대상·기간·부정·AND/OR 유지 |
| C01 진단표 | 문제 / 원인 / 영향 / 조치 | 원인 미확인은 미확인. 조치의 현재·계획·제안 구분 |
| C02 기준·격차 | 요구사항 / 제공 증빙 / 판단·격차 / 보완 | 자료 미제시≠미운영. 판단에는 기준+증빙 연결 |
| D01·D02 절차 | 단계 / 수행내용 / 확인된 입력·산출물·역할 | 단계는 동작+대상. 설명이 길면 세로 활동표 |
| D03 인계 | 역할별 활동 / 확인된 단계 / 전달 정보·승인 결과 | 업무 담당만 확인되면 책임표로 전환. 인계는 임의 생성 금지 |
| D04 분기 | 판정 질문 / 조건 충족·미충족 경로 / 결과 | AND는 모두, OR는 어느 하나. 미확인 결과를 면제로 표현 금지 |
| D05 순환 | 수행 / 점검 / 변경 / 재수행의 실제 환류 | 일회성 절차를 원으로 장식하지 않음 |
| E01·E02 | 분류는 부모·자식, 조직은 실제 역할·보고·승인 | 포함선과 보고선의 의미를 분리 |
| E05·E06 | 항목 대응표 또는 업무×역할×RACI | R/A/C/I 정의·배정 근거 필요. 조직도만으로 최종책임 배정 금지 |
| F02 영향 경로 | 외부동인 / 사업 작용경로 / 재무 영향 | 가능성·가정 유지. 비용·투자·손상·현금흐름 임의 치환 금지 |
| F03·F04 매핑 | 실제 연결·과제·목표·지표 | 다대다 보존. 목표값·성과·기여 크기는 별도 근거 필요 |
| G01~G03 시간 | 사건 연표 또는 기간·활동·산출물 계획표 | 실적/계획/목표 구분. 실제 기간과 개념 간격 구분 |
| G05 실적·목표 | 같은 지표의 실적 / 목표 / 차이 / 기간 | 서로 다른 기준연도·경계·방법을 한 궤적으로 연결 금지 |
| H01·H02 | 범주별 동일 지표 또는 동일 범위 반복 측정 | 연도 자체는 지표가 아님. 막대 영점·절단축 표시 검토 |
| H03·H04 | 공통 분모 구성비 또는 시작+증감=종료 | 배타성·가산관계·중복효과·합계 검사 |
| H05~H08 | 관측 분포 / 두 값의 쌍 / 민감도 / 정성 시나리오 | 원시자료·동일 모형·가정 필요. 정성 결과에 임의 수치 높이 금지 |

첨부에서 HTML 렌더를 구현했다고 표시한 것은 14개다. 이 저장소에서 48개를 자동 생성·검증한다는 뜻이 아니다. SVG 작성은 선택 실행 경로를 따르고, 직접 PPTX 채움은 해당 템플릿 구조와 보존 조건을 따른다.

## 8. 슬롯별 문구 가공

| 슬롯 | 권장 형태 | 의미 보존 예시 |
|---|---|---|
| 현황 | 대상 + 확인된 상태 | `사업장별 입력 양식 상이` |
| 원인 | 확인된 발생 요인 | `양식 차이로 재정리 발생(원문 설명)` |
| 영향 | 변화·결과 + 범위·가능성 | `추가 검토 발생 가능` |
| 활동·조치 | 동작의 대상 + 구체 행위 | `공통 입력 양식 도입(계획)` |
| 목표 | 지표·기간·수준 + 목표 상태 | 원문 목표를 명시. 실적과 별도 표기 |
| 조건·예외 | 적용 대상 + 판정조건 + 범위·기간 | `A와 B 모두 충족 시 적용` |
| 산출물 | 원문에서 확인한 결과물 | `승인 기록`, `제출 자료` 등 실제 근거가 있는 명칭 |
| 책임 | 실제 역할 + 해당 업무 | 담당 미확인은 `확인 필요`; 부서를 창작하지 않음 |

**문체**: 같은 열·동일 역할 노드는 같은 추상도와 명사형 종결을 사용한다. `검토`, `구분`, `도입(계획)`, `증가 가능`처럼 상태까지 남긴다. 모든 셀을 무조건 짧은 단어로 만들지 않는다. 직접 인용은 원문 문체를 보존할 수 있다.

**정리 순서**: 같은 뜻의 중복만 제거 → 공통 주어·범위 이동 → 대상·행동 구체화 → 조건·상태 복원 → 의미 단위 줄바꿈. 고유명사·기준명·Scope·법률 용어를 유사어로 임의 대체하지 않는다. 중요한 예외를 작고 흐린 각주나 발표자 노트에만 남기지 않는다.

**수치**: 값을 다시 계산·환산할 권한이 없는 본문 편집에서는 원자료 값과 단위를 유지한다. 허용된 계산은 별도의 원시값·식·단위·반올림 기록과 검산을 따른다. 결측값을 0으로 채우거나 여러 Scope·산정 방법을 무단 합산하지 않는다.

## 9. 노드와 연결선의 문법

| 시각 요소 | 의미 규칙 | 표시 |
|---|---|---|
| 노드 | 서로 구별되는 개념·활동·주체 하나 | 대상+상태 또는 동작+대상 |
| 그룹·경계 | 실제 포함 범위 또는 같은 분류 | 경계 이름·적용범위 |
| 순서 화살표 | 선행→후행 | 필요한 경우 단계·인계 이름 |
| 인과 화살표 | 원인→작용 경로→영향 | 근거와 `가능`, `원문 주장`, `가정` 상태 |
| 보고 화살표 | 보고자→수신자 | `보고`. 승인·감독은 별도 행위·방향으로 표시 |
| 매핑선 | 항목 간 대응·기여 | 관계 종류. 방향이 없으면 화살촉을 강제하지 않음 |
| 환류선 | 점검 결과가 변경·다음 수행으로 돌아감 | 무엇을 반영·재검토하는지 표시 |
| 점선·색상 | 선택 프로필과 페이지 범례에서 의미 고정 | 계획·가정·미확인을 문자로 함께 표시 |

**연결선 점검**: 출발·도착 노드, 관계 종류, 근거 ID, 조건·상태를 기록한다. 같은 모양의 선에 인과·보고·분류를 무표시로 혼용하지 않는다. 선이 텍스트를 지나가면 노드 배치·직교 경로·라벨 배경을 조정한다. 연결을 보기 좋게 만들려고 사실을 삭제하거나 우회 경로를 발명하지 않는다.

**선이 없어도 되는 경우**: 독립 주제·동일 기준 비교·단순 역할 목록은 표·위치·머리글로 관계를 전달한다. 관계가 분명히 표시된 표는 칸 사이마다 화살표를 추가할 필요가 없다.

## 10. 이너젠 화면에서 밀도·강조·분할

아래 수량은 초안용 권장 범위이며 자동 합격 기준이 아니다. 실제 글꼴 폭·조건 길이·독자·매체를 보고 조정한다.

| 요소 | 초안 권장 범위 | 초과·불편 시 조치 |
|---|---|---|
| 주구조 | 1개, 조건·예외 보조 패널 최대1개 | 독립 질문은 장표 분리 |
| 병렬 주제 | 2~4개 중심 | 상세 설명이 짧을 때만 더 배치 |
| 가로 절차 | 3~5단계 중심 | 긴 설명·조건이면 D02 세로형 또는 개요+상세 |
| 표 | 본문 3~6행, 의미 열 3~5개 중심 | 공통 헤더·행키를 유지한 행/대상 묶음 분할 |
| 관계도 | 4~7노드 중심 | 9노드·12연결선 부근부터 개요+상세 검토. 관련 유형의 제약도 확인 |
| 한 구획의 강조 | 핵심어·판단조건 1~2개 중심 | 전체 문장 볼드·파랑 사용 줄임 |
| 줄바꿈 | 단어·수치+단위·괄호 조건의 의미 경계 | 고립된 종결부와 불필요한 짧은 마지막 줄 재배치 |

**색·정렬**: 남색은 위계, 연회색/연블루는 의미 구획, 선택된 파랑은 판단조건, 빨간 밑줄은 핵심 예외·금지·기간 제한에 사용한다. 위험·기회·계획·미확인은 색만으로 구분하지 않는다. 표 셀은 가로·세로 가운데, 긴 도식 설명은 왼쪽 정렬을 유지한다. 장식용 숫자·사진·그림자·둥근 카드 반복을 기본값으로 넣지 않는다.

**v4.2 교육 프로필의 실행값**: 1040×720px / 780×540pt에서 제목24pt=32px, 거버닝20pt≈26.667px, 본문·표·최종14pt≈18.667px, 소제목16.5pt=22px, 출처10pt≈13.333px. 본문 영역 x48/y174/944×378px, 구획 간16px, 내부24px는 v10의 초기 배치값이다. 다른 비율에는 재배치한다. 확인 화면·SVG·잠금값은 px이며 이미 확인된 px를 다시 환산하지 않는다.

**넘침 수정 순서**: 중복 표현 정리 → 공통 정보 머리글 이동 → 열 너비·내부 여백·줄바꿈 재배치 → 가로/세로 구조 변경 → 핵심/상세 분리 → 다음 장으로 분할. 본문14pt가 확인된 교육자료를 12pt로 낮춰 해결하지 않는다. 고정 장수·문구 보존 때문에 해결할 수 없으면 구체적인 충돌을 표시하고 해당 변경만 사용자와 조정한다.

**분할 시 보존**: 기준·단위·범위·헤더 반복, `계속`·연결 단계 표시, 이동한 근거 ID의 목적지 기록. 핵심 조건·반대 근거·예외를 부록에만 숨기지 않는다. 축·범위·정량/정성 표시·계획 상태도 다음 장에 남긴다.

## 11. 본문과 거버닝·하단 메시지 연결

| 역할 | 작성 기준 |
|---|---|
| 제목 / 부제목 | 목차 번호와 연결되는 분류·대상 명사구 |
| 거버닝 | 명시적 주어 + 본문이 지지하는 핵심 판단 + 필요한 조건. `합니다` 체 한 문장 |
| 본문 | 판단에 필요한 관계·조건·근거를 표·도식으로 표현. 명사형 중심 |
| 하단 최종 | 필요한 증빙·검토·다음 행동을 한 문장으로 표현. 실무 제안이면 제안임을 명시 |
| 출처 | 문서명+실제 PDF 파일 페이지. 상세 문단·원문·ID는 제작 근거 기록에 유지 |

v11의 주어 시작 원칙을 유지한다. 주어를 다양하게 하려고 원문에 없는 조직 책임을 만들지 않는다. 정보가 부족하면 분류형 제목을 질문형으로 바꾸기보다 거버닝에 `제공 자료에서는 ... 확인되지 않아 ... 추가 확인이 필요합니다`처럼 한계를 명시한다. 권고를 의무로 강화하는 `해야 합니다`를 사용하지 않는다.

**양방향 점검**: 거버닝의 주장·조건을 본문에서 찾기 → 본문의 중요한 내용이 거버닝과 충돌하지 않는지 확인 → 하단의 행동이 확인된 격차·근거·권고에 연결되는지 확인. 거버닝과 하단 문장을 그대로 복제하지 않는다.

## 12. 제작 기록·검사·수정

**간결한 기록**: 기존 프로젝트의 명세·분석 기록에 아래 표를 둔다. 같은 정보를 담은 기록이 있으면 새 파일을 중복 생성하지 않는다. 발표 장표에 내부 근거 ID·파일 경로·검사 코드 전체를 넣지 않는다.

| 장표 | 독자 질문 | 행키·주관계 | 선택 구조·이유 | 근거·이동 목적지 | 미확인·충돌 |
|---|---|---|---|---|---|
| P01 | 한 가지 판단 질문 | 문제/비교기준/단계 등 | C02 등, 근거 보존 이유 | C01→본문1행 등 | 담당 확인 필요 등 |

| 검사층 | 확인할 것 | 통과의 의미 |
|---|---|---|
| 근거 연결 | 원문·위치·ID 존재, 수치·단위·기간·조건 대응 | 연결이 유효함. 의미 정확성을 자동 보증하지 않음 |
| 의미 검토 | 사실/계획, 인과/병렬, 범위·부정·AND/OR, 격차 판단 | 가공 문구와 도식이 원문보다 강한 주장으로 바뀌지 않음 |
| 화면·출력 | 실제 글꼴, 넘침·겹침·정렬·편집성·색상 | 실행 경로에서 실제 검사한 범위만 보고 |

| 결함 | 수정·확정 처리 |
|---|---|
| 중요 수치·연도 충돌 | 양쪽 원문 유지, 확정 결론 보류 또는 확인 필요로 명시. 임의 선택 금지 |
| 근거 없는 인과·보고선·좌표·점수 | 관계·차트 제거 또는 근거 확보. 관련 사실은 표로 보존 |
| 조건·예외·부정·범위 손실 | 본문에 복원. 거버닝도 같은 조건으로 수정 |
| 참조 존재하나 의미 불일치 | 해당 문구 수정. 출처 ID만 추가해 해결했다고 보지 않음 |
| 가독성·편집성 결함 | 배치·구조·분할 수정, 선택 실행 경로에서 다시 검사 |
| 검사 환경·측정값 없음 | `미검사`로 기록. 통과나 실행 완료로 보고하지 않음 |

이 검토는 기존 제작 절차에서 수행할 품질 판단이며 별도 승인 UI·추가 게이트·자동 검사기를 설치하지 않는다. 중요한 사실·관계 오류를 해결하지 않은 내용을 확정된 성과로 제시하지 않는다. 오류가 제한된 구획에만 있으면 확인된 부분의 작성은 계속할 수 있다.

완료 보고에는 변경한 규칙·파일, 확인한 근거, 실제 검증 범위, 남은 미확인·현재성·출력 한계를 구분한다. 원본과 이전 버전을 보존한다. 이번 규칙 보완 자체는 법령 최신화나 새 PPTX의 렌더 검증이 아니다.
